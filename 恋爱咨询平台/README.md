# 恋爱咨询台

把遇到的困难写下来，MiMo 会**先检索课程**，再按课程里的机制回答；答案必须带决策词、机制、可执行动作和停止条件，并给出可点开的课程引用。

- 课程库：179 节主课 + 6 节补丁课 + 2 份总纲，共 187 条索引
- 模型：`mimo-v2.6-pro`（Token Plan 端点）
- 依赖：**零第三方库**，只用 Python 标准库

## 启动

```bash
cd "E:/一门给年轻人的恋爱成长课/恋爱咨询平台"
python server.py           # 默认 8770
python server.py 8800      # 或指定端口
```

打开 <http://127.0.0.1:8770>

需要环境变量 `MIMO_API_KEY`（已在本机设置）。可选：

| 变量 | 默认 | 说明 |
|---|---|---|
| `MIMO_BASE_URL` | `https://token-plan-cn.xiaomimimo.com/v1` | 接口地址 |
| `MIMO_MODEL` | `mimo-v2.6-pro` | 模型名；`mimo-v2.6-flash` 更快更省，首字约 0.8s vs 1.1s |
| `MIMO_THINKING` | `off` | 设 `on` 恢复思考链；关掉后首字从 5.4s 降到 0.8s |

启动时会自检模型名是否仍在上游可用列表里（`GET /models`），不在就直接把可用清单打到终端——上游会下架模型（`mimo-v2.5` 已下架，请求返回 400 `Unsupported model`），不自检的话服务照常启动、等用户提问才炸，很容易被误判成"平台坏了"。

## 它是怎么工作的

```
用户输入
  → 安全关键词检查（自杀/暴力/跟踪/控制…）→ 命中则先注入求助信息，模型被禁止给推进技巧
  → 本地 BM25 检索（字 bigram + 概念标签 + 标题加权 + 意图路由）→ 取前 4 节
  → 组装 system prompt：角色铁律 + 五向决策 + 证据分级 + 检索到的课程片段
  → MiMo 流式返回 → 前端边收边渲染 → 完成后附课程引用卡片
```

三个设计取舍：

1. **安全判定放在代码里，不放给模型。** 危机与暴力由关键词表判定，命中后固定文本先于模型输出，避免模型"漏判"。
2. **检索用两段式打分。** 标题/概念/目标算"主题分"，正文只做确认（权重 0.22）。只按正文打分时，《共同面对丧失》会被"慢""关系"这类词误召回。
3. **查询词要过滤。** "不是""一步""继续"这类虚词 bigram 在标题里有权重，不过滤会把《道歉要包含改变》顶到《暴力与控制》前面。

## 引用可核验（硬引用）

回答里的每个【第 N 课】都要能对得上原文，分四层保证：

1. **给模型看原文段落。** 检索阶段除了整课摘要，还会从被命中课程里抽出 1–2 段原始段落（按段落打分，命中段落不足时用「核心概念/机制」段兜底）。
2. **要求模型照着原文引。** system prompt 规定：引用后必须跟「对应原文：……」，且只能用材料里给的原文，不能改写；材料没支持的判断不许挂课程编号，改标 `[C]`。
3. **服务端核验编号。** 回复生成后，用正则抓出所有「第 N 课」，逐个比对本次检索结果：
   - 命中 → `citations.verified`
   - 不在结果里 → `citations.unverified`，前端标黄提示「未在检索结果中」
4. **服务端核验原文。** 再判断被引内容是否真的出自该课：把该课**全部小节原文**归一化（只留汉字与字母数字，丢掉标点/空白/加粗记号）后，看回答里有没有连续 10 个"实字"与之吻合。
   - 吻合 → `citations.grounded`
   - 不吻合 → `citations.ungrounded`，前端提示「只复述了编号、没引原文」

两个取舍值得说明：

- **核验集用整课原文，不是只给用户看的 2 条摘录。** 模型在上下文里能看到该课整段摘要，引用第三段是合法的；若只拿 2 条摘录去比，会把"引对了但不在摘录里"误判成编造——误报比不核验更糟，会让人不再信任核验条。实测就有一例：模型引了第 9 课一句话，正好不在 2 条摘录里，但确在该课全文中，旧逻辑判成编造。
- **比对前做标点归一化。** 模型常把原文的 `“”` 写成 `""`、把 `，` 写成 `,`；这类纯排版差异不该算作没引原文。归一化后仍要求连续 10 个实字吻合，编造内容照样会被抓出来（单元用例覆盖：换引号→通过，编造内容→不通过，只提编号→不通过，假课号→不通过）。

前端每轮回答下方显示 **引用核验 2/2 · 编号全部可核验**；点课程卡片先看**原文摘录**（可逐字比对），再点「读全文」看整课。

> 这一层的意义：模型可以编一个听起来合理的说法，但它很难在编号和原文两侧同时编圆。核验不通过时你能立刻看见，而不是被一段流畅的回答骗过去。

## 判断识别（五档）

`ADVANCE / MAINTAIN / OBSERVE / DE_ESCALATE / EXIT` 由服务端从回答里识别，规则有先后：

1. 优先取带标签的「判断：XXX」——正文里随口提到别的词不会被误取；
2. 没有标签就取全文中**最早出现**的那个词。不能按固定顺序取，否则正文先写 OBSERVE、结论才是 EXIT 时会被判成 OBSERVE（旧实现按元组顺序取，已修）；
3. **危机场景兜底 EXIT**：安全路径不允许出现「没有判断」。

判断词不能只从开头若干字符里找：危机路径会在最前面插入 238 字的安全提示块，模型的判断词会被挤到后面去，导致徽章空白（已修）。

## 用户中途关页面

SSE 是一次长写，用户随时可能走开。写失败会被转成 `ClientGone` 并静默收尾，只在终端留一行 `[client gone]`，不计入错误数。

不这么做的话，日志里会出现「写失败 → 想发错误消息 → 又写失败 → 兜底写 JSON → 还是失败」的三层嵌套 `ConnectionAbortedError` 加一段 500 堆栈，看着像服务崩了，实际只是对面没人接了。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat/stream` | SSE 流式；事件 `delta` / `done` / `error` |
| POST | `/api/chat` | 非流式，返回完整 JSON（便于脚本测试） |
| GET | `/api/lesson?no=29` | 单课全文，供引用卡片展开 |
| GET | `/api/stats` | 课数与阶段/机制层分布 |
| GET | `/api/health` | 模型与密钥状态、课数 |

## 已知限制

- **检索是词面匹配**，没有语义向量。用户用非常规说法时可能召回偏；缓解手段是同义词表（`SYNONYMS`）与意图路由（`ROUTES`），需要持续补。
- **不做多轮记忆持久化**：对话只在浏览器内存里，刷新即清空。这是有意的隐私取舍。
- **不替代专业帮助**：不做诊断、不给药物与法律意见；涉及医疗、避孕、性病、用药会要求以当前权威信息核验。
- **危机场景仍需人工兜底**：关键词覆盖有限（如"我不想活了"能命中，"我撑不下去了"未必），不要把本工具当作唯一安全网。
