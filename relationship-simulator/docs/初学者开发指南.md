# HeartFlow 初学者开发指南

这份指南只讲“改哪里、怎么验证、出错先看什么”。不需要先读完整个项目。

## 1. 先记住五个区域

| 你想改什么 | 主要目录 | 不要直接改什么 |
|---|---|---|
| 页面布局和按钮 | `public/index.html`、`public/styles.css` | 不要把业务逻辑写进 HTML |
| 浏览器业务逻辑 | `public/modules/` | 不要继续把大段逻辑堆进 `public/app.js` |
| 本地 API | `server/` | 不要在浏览器代码里放 API Key |
| Relationship Intelligence | `.agents/skills/relationship-coach-cn/runtime/` | 不要从页面复制一份 runtime 逻辑 |
| 长篇教材 | `long-simulation/` | 不要手改生成文件 `public/modules/content/long-content-manifest.js` 与 `public/modules/content/long-content/chapter-XX.js` |

`public/app.js` 是装配入口：它把状态、控制器和渲染模块接起来。新增功能时，优先创建一个职责单一的模块，再在这里接线。

## 2. 最小开发循环

在 PowerShell 中进入项目：

```powershell
Set-Location 'E:\一门给年轻人的恋爱成长课\relationship-simulator'
```

先运行基线：

```powershell
npm.cmd test
npm.cmd run check:circular
```

修改后再次运行同样两条命令。测试失败时，先看输出中第一个 `not ok`、`ERR_` 或 `AssertionError`；后面的失败有时只是同一个原因引起的连锁反应。

启动页面：

```powershell
npm.cmd start
```

浏览器打开 `http://localhost:3000`。如果出现 `EADDRINUSE`，说明 3000 端口已经被另一个程序占用；先关闭旧服务，或在本地 `.env` 中换一个 `PORT`。

## 3. 两条 API 边界不要混淆

| 接口 | 用途 | 是否可能访问远程模型 | 是否需要 Key |
|---|---|---:|---:|
| `POST /api/relationship-intelligence` | 本地证据、状态、决策和匿名 Memory | 否 | 否 |
| `POST /api/chat` | 模型生成、优化和计划 | 是 | 是，放在服务端 `.env` |

Relationship Intelligence 的浏览器调用链是：

```text
public/modules/intelligence/state.js
→ client.js
→ server/relationshipIntelligence.js
→ shared runtime
→ controller.js
→ render-intelligence.js
```

查错时按这个顺序看，通常比在整个仓库搜索更快。

## 4. 隐私规则

- 匿名结构化长期记忆默认关闭。
- 未同意时，分析可以显示，但 `saveState()` 会从 localStorage 副本中移除 `lastResult` 和 `memory`。
- 同意后也只能保存 `case_` 匿名标识和 runtime 校验过的结构化摘要；不能把原始聊天塞进 memory。
- API Key 只放在未提交的 `.env`，不要写进 HTML、JavaScript、测试输出或截图。
- 新增网络调用前，先确认它是否真的需要原始对话；大多数检索只需要脱敏关键词。

## 5. 常见改动模板

新增一个纯函数时：

1. 在相应 `public/modules/<领域>/` 创建文件。
2. 在 `test/` 先写一个会失败的测试。
3. 实现最小代码让测试通过。
4. 运行 `npm.cmd test`。
5. 运行 `npm.cmd run check:circular`。

修改长篇章节后额外运行：

```powershell
npm.cmd run build:index
```

生成成功后不要继续手改 `long-content-manifest.js` / `long-content/chapter-XX.js`，否则下次构建会覆盖你的修改。

## 6. 完成前检查

**先跑质量门禁（一条命令做完）：**

```bash
npm test
# = node --test  +  check-circular  +  check-conventions
```

只要有一条失败就不算完成。想快速迭代可以先 `npm run test:unit`（只跑单测），
提交前仍要跑完整的 `npm test`。

门禁之外再人工确认：

- 页面原有聊天、角色、A/B/C、回放、课程和模型代理仍能工作。
- 新功能在模型不可用时有明确的本地失败提示，不阻断其他功能。
- 动态文本进入 `innerHTML` 前经过 `escapeHtml`，或使用 `textContent`。
- 没有新增循环依赖。
- `git diff --check` 没有空白错误。
- `git status --short` 中没有 `.env`、密钥、Cookie、原始私聊或意外生成的大文件。

## 7. 约定检查器在拦什么

`scripts/check-conventions.mjs` 是**项目口头约定的可执行版本**，不是通用 linter。
它拦的都是这个仓库真出过问题的地方：

| 规则 | 拦什么 | 为什么 |
|---|---|---|
| `html-interpolation-escape` | HTML sink 里的文本类插值没过 `escapeHtml` | XSS，全库最高优先级 |
| `state-write-bypass-mutate` | `mutate` 回调外直写 / `delete` state 字段 | 不广播 `onStateChange`，面板不刷新 |
| `layer-direction` | `core` 反向依赖 `render`/`voice`/`intelligence`（含 I/O 的部分） | 分层被破坏后依赖图会失控 |
| `single-escape-html` | 第二份 `escapeHtml` 实现 | 修一处漏一处 |
| `single-clamp-score` | 自拼 `Math.max(0, Math.min(100, ...))` | 边界策略要改就得改 12 处 |
| `single-date-key` | 自拼 `YYYY-MM-DD` 日期键 | 三种"今天"口径曾让跨零点错一天 |
| `render-module-test-coverage` | `public/modules/render/*.js` 没被任何测试 import | 渲染层是唯一没有回归网的地方 |

**新增代码的两条硬约定：**

1. 新增 `public/modules/render/*.js` 必须自带测试（`test/*.mjs` 里 import 它）。
   确实无法测的要在 `RENDER_COVERAGE_ALLOWED` 里写明理由——这张表是**冻结的**，只减不增。
2. 需要 0–100 取整时调用 `core/number.js` 的 `clampScore`（非有限→0）或
   `clampScoreOrNull`（未评分→null），不要自己写 `Math.max(0, Math.min(100, ...))`。

规则的豁免清单都写在检查器源码里，每条注明了原因。**要新增豁免，先改文档说清为什么。**

## 8. 部署时的前置条件

`server/relationshipIntelligence.js` 会静态 import 项目目录**之外**的运行时：

```
<项目根>/../.agents/skills/relationship-coach-cn/runtime/index.mjs
```

也就是说只拷贝 `relationship-simulator/` 一个目录去部署，`node server/index.js`
会在 ESM 静态解析阶段直接失败——整个服务起不来，不只是 `/api/intelligence` 不可用。

部署时必须同时带上同级的 `.agents/skills/relationship-coach-cn/runtime/`。
