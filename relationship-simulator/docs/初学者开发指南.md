# HeartFlow 初学者开发指南

这份指南只讲“改哪里、怎么验证、出错先看什么”。不需要先读完整个项目。

## 1. 先记住五个区域

| 你想改什么 | 主要目录 | 不要直接改什么 |
|---|---|---|
| 页面布局和按钮 | `public/index.html`、`public/styles.css` | 不要把业务逻辑写进 HTML |
| 浏览器业务逻辑 | `public/modules/` | 不要继续把大段逻辑堆进 `public/app.js` |
| 本地 API | `server/` | 不要在浏览器代码里放 API Key |
| Relationship Intelligence | `.agents/skills/relationship-coach-cn/runtime/` | 不要从页面复制一份 runtime 逻辑 |
| 长篇教材 | `long-simulation/` | 不要手改生成文件 `public/modules/content/long-content-manifest.js` 与 `public/modules/content/long-content/chapter-XX.js` |

`public/app.js` 是装配入口：它把状态、控制器和渲染模块接起来。新增功能时，优先创建一个职责单一的模块，再在这里接线。

## 2. 最小开发循环

在 PowerShell 中进入项目：

```powershell
Set-Location 'E:\一门给年轻人的恋爱成长课\relationship-simulator'
```

先运行基线：

```powershell
npm.cmd test
npm.cmd run check:circular
```

修改后再次运行同样两条命令。测试失败时，先看输出中第一个 `not ok`、`ERR_` 或 `AssertionError`；后面的失败有时只是同一个原因引起的连锁反应。

启动页面：

```powershell
npm.cmd start
```

浏览器打开 `http://localhost:3000`。如果出现 `EADDRINUSE`，说明 3000 端口已经被另一个程序占用；先关闭旧服务，或在本地 `.env` 中换一个 `PORT`。

## 3. 两条 API 边界不要混淆

| 接口 | 用途 | 是否可能访问远程模型 | 是否需要 Key |
|---|---|---:|---:|
| `POST /api/relationship-intelligence` | 本地证据、状态、决策和匿名 Memory | 否 | 否 |
| `POST /api/chat` | 模型生成、优化和计划 | 是 | 是，放在服务端 `.env` |

Relationship Intelligence 的浏览器调用链是：

```text
public/modules/intelligence/state.js
→ client.js
→ server/relationshipIntelligence.js
→ shared runtime
→ controller.js
→ render-intelligence.js
```

查错时按这个顺序看，通常比在整个仓库搜索更快。

## 4. 隐私规则

- 匿名结构化长期记忆默认关闭。
- 未同意时，分析可以显示，但 `saveState()` 会从 localStorage 副本中移除 `lastResult` 和 `memory`。
- 同意后也只能保存 `case_` 匿名标识和 runtime 校验过的结构化摘要；不能把原始聊天塞进 memory。
- API Key 只放在未提交的 `.env`，不要写进 HTML、JavaScript、测试输出或截图。
- 新增网络调用前，先确认它是否真的需要原始对话；大多数检索只需要脱敏关键词。

## 5. 常见改动模板

新增一个纯函数时：

1. 在相应 `public/modules/<领域>/` 创建文件。
2. 在 `test/` 先写一个会失败的测试。
3. 实现最小代码让测试通过。
4. 运行 `npm.cmd test`。
5. 运行 `npm.cmd run check:circular`。

修改长篇章节后额外运行：

```powershell
npm.cmd run build:index
```

生成成功后不要继续手改 `long-content-manifest.js` / `long-content/chapter-XX.js`，否则下次构建会覆盖你的修改。

## 6. 完成前检查

- 页面原有聊天、角色、A/B/C、回放、课程和模型代理仍能工作。
- 新功能在模型不可用时有明确的本地失败提示，不阻断其他功能。
- 动态文本进入 `innerHTML` 前经过 `escapeHtml`，或使用 `textContent`。
- 没有新增循环依赖。
- `git diff --check` 没有空白错误。
- `git status --short` 中没有 `.env`、密钥、Cookie、原始私聊或意外生成的大文件。
