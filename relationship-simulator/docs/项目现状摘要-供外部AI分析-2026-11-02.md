## 0. 一句话定位

本地单人使用的中文恋爱成长练习工具：原生 ESM 前端 + 零 npm 依赖的 Node 服务 +
`localStorage` 持久化 + Python 语音 sidecar。**没有也不打算引入**数据库、向量库、
Redis、消息队列、多租户或构建链。任何建议如果默认需要这些基础设施，都与本项目错位。

## 2. 双通道模型调用（今天的核心变化）

一次「生成女方对话」是**两次独立的模型调用**，不是一次调用让模型同时扮演教练和女方。
拆分的直接动机：合并时她的回复会漏出教练腔和分析口吻，且合并 prompt 更容易撞上游超时。

| 通道 | 思维链 | 输出预算 | 输出格式 | 实测 |
| --- | --- | --- | --- | --- |
| 她（`HER_LANE`） | 关闭 | `max_completion_tokens=200` | 纯文本，可多条气泡 | 首次可见 P50 **1.2–6.7s**，长尾可到 17–24s |
| 教练（`COACH_LANE`） | 关闭 | 服务端默认 4096 | `response_format=json_object` | 完成 P50 **24.2s**，最慢 49.1s |

拆分前角色回复实测 19.95s；先关思考（`148849c`）降到 4.24s，再给教练关思考（`7c04a8c`）
把整轮从「她 20s + 教练 48s」压到今天的量级。

**教练通道关思考的 A/B 依据**（同提示词、同裁判配置，各 5 用例）：

| 指标 | 思考开 | 思考关 |
| --- | --- | --- |
| 教练 P50 | 73.97s | 24.22s |
| 504 超时 | 1 次 | 0 次 |
| 输出 token | — | −38% |
| 回答问题 / 可发送 / 三条有别 / 像真人 | 3/5 · 4/5 · 3/5 · 4/5 | **5/5 ×4** |

四项行为判定全部持平或更好，所以这不是「快一点换笨一点」，是纯延迟代价。
样本 5，方向明确但不具统计显著性。原始数据：
`docs/verification/ab-p0-armA-thinking-on.md`、`ab-p0-armB-thinking-off.md`。

**JSON 模式的作用**：开之前 5 用例里有 1 次教练输出不是合法 JSON，整轮 A/B/C 落到本地模板；
开之后 0 次。上游不稳仍在：本轮观测到 1 次 504（120s 超时）和一次浏览器实跑 ~197s（超时 + 1 次重试）。

## 3. 模型与代理

- 上游：MiMo `mimo-v2.6-flash`，经本地 `server/llmProxy.js` 转发，`stream: false`。
- 思考默认开启，**不透传就关不掉**（实测 48 个输出 token 里 29 个是推理 token）。
- 代理只在 `chat_completions` 模式转发 `thinking`；`responses` 模式走 `reasoning.effort`。
- `MAX_ATTEMPTS=2`、`UPSTREAM_TIMEOUT_MS=120s`，最坏一轮 ~480s。
- 因此生成中的按钮现在是**就地取消入口**并显示已等秒数，不再是禁用的「生成中…」。

**尚未做**：SSE 流式。曾建议押后的理由是本地已用前端分段模拟打字；实测数据是 disabled + 流式
可把首次可见从 1.80s 降到 0.80s，但流式会带出 `delta.reasoning_content`，需要额外过滤。
这是一个待评估选项，不是已排除的结论。

## 4. 质量守门：两层，别混为一谈

`npm test`（零成本、常驻）验证「已覆盖的行为没违反现有断言」。它**证明不了**角色自然、
记忆可靠或教练不误读——今天的两个真实缺陷都是 900+ 全绿时漏掉的，因为都发生在模块接缝处。

`npm run eval:behavior`（付费、opt-in）：
- 默认**干跑**，只打印用例数、token 与费用预估；确认要花钱必须显式加 `--yes`。
- 5 用例 × 3 次调用（角色 / 教练 / 模型裁判）≈ **¥0.02**，走本地代理，脚本不读密钥。
- 单用例失败不丢整轮数据；免费诊断记录教练 `finish_reason`、推理 token、解析报错，
  把「为什么落到本地兜底」从猜测变成可读证据。
- `--coach-json` / `--coach-nothinking` 用于 A/B。

裁判也是 MiMo，且被测与裁判同源，存在自我偏好风险；`answered_question` 这类语义判定
无法用纯词面重合做确定性校验（实测「什么类型的展」与正确答案「摄影展」零 bigram 重合）。

## 5. 教练的底线契约（产品差异点）

- 只分析**可观察信号**：提问、主动联系、回应前文、明确邀约。不推断心理，不给「喜欢百分比」。
- 输出必须区分：行为事实 / 假设+反证 / 未知 / 置信度。缺证据就写未知。
- 模拟生成的回应显式标明为虚构情境，不得充当现实结果证据。
- A/B/C 三条建议必须是**三个互不相同的沟通动作**（今日新加，此前只约束「必须是直接回应」，
  导致模型常交三条同一动作的说法），最多一条以问句结尾，两条去掉语气词后同义即判不合格。
- 反 PUA：不输出操控手法实施建议；PUA 识别模式下只做手法识别 + 防御替代。

## 6. 现状与缺口

| 能力 | 现状 | 缺口 |
| --- | --- | --- |
| 长期记忆 | 关键词 + 时间线 + 会话摘要，`localStorage` | 无结构化事实、无来源追溯、无冲突取代、无 `simulation/real` 作用域隔离 |
| 角色连续性 | 人设固定，无时间感知 | 无世界书 / Author's Note、无未完成约定、无知识边界分离 |
| 训练闭环 | 179 课 + 微训练 + 连续约会 + 错题本 | 教材未参与个性化训练决策，无分支回放 |
| 模式 | `trainingMode === "pua" ? "pua" : "anti"` 散落多处 | 加 `companion` 会被静默识别成 `anti`；需枚举收敛 |
| 关系判断 | `core/investment.js` 与 `server/relationshipIntelligence.js` 两套 | 决策枚举未统一 |

## 8. 给外部 AI 的硬约束

提出任何方案时请遵守：

1. **不要**建议重置/清理未提交文件，不要建议 `git checkout`/`restore`/`reset`/`clean`。
   本项目本会话已发生过一次 `git checkout --` 覆盖用户 WIP 的事故。
2. **不要**建议引入数据库、向量库、Redis、微服务、构建链或多租户基础设施。
3. **不要**建议用付费 API 做大规模测试。付费调用必须 opt-in、先报价、可干跑。
4. **不要**建议输出「喜欢概率」「对方真实想法」这类不可验证的心理判断。
5. 谈延迟请给可复现的测量方法，不接受只改 prompt 的「应该会更快」。
