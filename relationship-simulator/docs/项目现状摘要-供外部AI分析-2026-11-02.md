## 1. 定位与硬边界

本地**单人使用**的中文恋爱成长练习工具。用户跟一个模拟角色对话，系统同时给出教练分析、
三条可发送的回复建议、以及基于 179 课教材的复盘。目标是练习真实沟通能力，不是谈恋爱替代。

**没有、也不打算引入**：数据库、向量库、Redis、消息队列、微服务、构建链、多租户、鉴权体系、
任何服务端持久化。

```
原生 ESM 前端（无框架、无打包）
  + 零 npm 依赖的 Node >= 18 服务（静态托管 + LLM/TTS/搜索代理）
  + localStorage 持久化
  + 本地 Python 语音 sidecar
```

任何默认需要上述基础设施的建议，都与本项目错位。

## 4. 双通道模型调用（本轮核心变化）

一次「生成女方对话」是**两次独立调用**，不是一次调用让模型同时扮演教练和女方。

动机：合并 prompt 下她的回复会漏出教练腔与分析口吻，且更容易撞上游超时。
拆分后暴露的真实缺陷见 §6。

| 通道 | 思维链 | 输出预算 | 输出格式 | 实测耗时 |
| --- | --- | --- | --- | --- |
| 她（`HER_LANE`） | **关闭** | `max_completion_tokens=200` | 纯文本，可拆多条气泡 | 首次可见 P50 **1.2–6.7s**，长尾 17–24s |
| 教练（`COACH_LANE`） | **关闭** | 服务端默认 4096 | `response_format=json_object` | 完成 P50 **24.2s**，最慢 49.1s |

拆分前角色回复实测 **19.95s**；先关她的思考降到 4.24s，再关教练的思考把整轮压到上面的量级。

**教练关思考的 A/B 依据**【实测，同提示词、同裁判配置，各 5 用例】：

| 指标 | 思考开 | 思考关 |
| --- | --- | --- |
| 教练 P50 | 73.97s | **24.22s** |
| 教练最慢 | 88.56s | 49.06s |
| 504 超时 | 1 次 | 0 次 |
| 输出 token | — | −38% |
| 回答问题 / 可发送 / 三条有别 / 像真人 | 3/5 · 4/5 · 3/5 · 4/5 | **5/5 ×4** |

四项行为判定全部持平或更好 ⇒ 这不是「换一点质量买速度」，是纯延迟代价。
原始数据：`docs/verification/ab-p0-armA-thinking-on.md`、`ab-p0-armB-thinking-off.md`。

**JSON 模式的作用**【实测】：开之前 5 用例里 1 次教练输出不是合法 JSON，整轮 A/B/C 落到本地模板；
开之后 0 次。

**上游配置**【读码】：`MiMo mimo-v2.6-flash`，`stream:false`，`MAX_ATTEMPTS=2`，
`UPSTREAM_TIMEOUT_MS=120s` ⇒ 最坏一轮约 **480s**。MiMo 思考**默认开启**，代理不透传就关不掉
（实测 48 个输出 token 里 29 个是推理 token）。

**尚未做**：SSE 流式。曾建议押后（本地已用前端分段模拟打字）；实测 `disabled + 流式`
可把首次可见 1.80s → 0.80s，但流式会带出 `delta.reasoning_content`，需要额外过滤防泄漏。
这是**待评估选项**，不是已排除的结论。

## 5. 质量守门：两层，不要混为一谈

### 5.1 `npm test`【零成本、常驻、922 通过】

= `node --test` + `check-circular.mjs` + `check-conventions.mjs`（上面 §3 的 7 条 R 规则）。

它证明的是「已覆盖的行为没违反现有断言」。**它证明不了角色自然、记忆可靠或教练不误读**——
本轮两个真实缺陷都是在 900+ 全绿的情况下漏掉的，因为它们发生在**模块接缝处**，
而单元测试把接缝两侧分别桩成了常量。

一个具体教训：`buildHerSystemPrompt` / `buildCoachSystemPrompt` 这两个**真正上线**的构造函数
此前**没有任何测试**（测试全打在已死的合并式 prompt 上）。现已重定向。

### 5.2 `npm run eval:behavior`【付费、opt-in】

行为层评测，与单元测试严格分开：

- 默认**干跑**：只打印用例数、token 与费用预估，**不发任何请求**；要花钱必须显式 `--yes`。
- 5 用例 × 3 次调用（她 / 教练 / 模型裁判）≈ **¥0.02**。
- 走本地代理，脚本不读密钥 ⇒ 报告里也不会出现密钥。
- 单用例失败**不丢整轮数据**（上游会 504，钱已花完不能白烧）。
- 免费诊断：记录教练 `finish_reason`、推理 token 数、JSON 解析报错原文，
  把「为什么落到本地兜底」从猜测变成可读证据。
- `--coach-json` / `--coach-nothinking` 用于 A/B。

**已知的评测局限（请不要把它的结论当真）**：
1. 裁判也是 MiMo，**被测与裁判同源**，存在自我偏好风险。
2. n=5，比率只有方向性。
3. `answered_question` 这类语义判定**无法用纯词面重合做确定性校验**——实测她问「什么类型的展」
   与正确答案「摄影展」之间 bigram 重合为 0；反过来「回避答案」的模板与她原话反而有重合。
   所以确定性层只测结构，语义层只能上裁判。

## 6. 教练的产品底线（这是差异化所在）

- 只分析**可观察信号**：提问、主动联系、回应前文、明确邀约。**不推断心理，不给「喜欢百分比」。**
- 输出必须分离：行为事实 / 假设+反证 / 未知 / 置信度。缺证据就写未知。
- 模拟生成的回应显式标明为**虚构情境**，不得充当现实关系证据。
- **A/B/C 必须是三个互不相同的沟通动作**：A 承接她的内容并给出态度；B 用轻松/幽默说同一件事；
  C 提一个她容易接的具体问题或下一步。最多一条以问句结尾；两条去掉语气词与标点后同义即判不合格。
  她若提问，A 必须先把那个问题答掉（只用她提问前用户已说过的信息）。
- 反 PUA：不输出操控手法实施建议。PUA 识别模式下只做「手法识别 + 识别信号 + 防御替代」。
- 兜底必须诚实：本地模板只能复述用户说过的话，无权新增事实；她在提问而用户没给细节时，
  界面明示「这是骨架，请你自己补进去再发送」。
