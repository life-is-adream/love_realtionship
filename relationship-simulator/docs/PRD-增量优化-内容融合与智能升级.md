# HeartFlow 增量 PRD：内容融合与智能升级

> 版本：v1.0 ｜ 撰写：产品经理 许清楚 ｜ 范围：方向①内容融合 + 方向③智能升级 + 方向④体验与角色扩容
> 性质：增量 PRD，不重写既有产品，基于现有文件结构叠加能力。项目根目录：`E:\一门给年轻人的恋爱成长课\relationship-simulator`

---

## 一、产品目标

本次增量在现有 HeartFlow（纯 Node.js + Vanilla JS，零 npm 依赖，三栏聊天训练台）基础上，达成三个正交目标：

1. **内容融合（最高优先）**：把 17.4 万字长篇资产从"文件夹里的小说"变成"产品内的可练教材"。用户能在 App 内阅读 10 章长篇，在关键对话节点介入练习（替换男方回复 → AI 接续女方反应 → 与原著对照），并对照每章的"恋爱大师复盘"评估自己的练习。

2. **智能升级**：把现在"手动选 7 阶段"升级为"AI 基于对话自动判断关系阶段（状态机）+ 手动覆盖兜底"；基于长篇语料建立教练四维评分基准，抑制本地启发式评分的虚高；把散落在 `app.js` 的 prompt 构建逻辑抽离成独立模块，便于版本管理。

3. **体验与角色扩容**：让产品在手机上真正可用（从"三栏垂直堆叠"升级为"可切换 Tab 布局"）；增加场景化训练剧本（预设情境起点）；把长篇角色夏紫桐做成与三位内置角色并列的丰满内置角色。

> 贯穿约束：反 PUA、边界优先、同意优先。所有功能不得引入话术套路、操控或焦虑制造。零 npm 依赖优先。

---

## 二、用户故事

- **US1（内容融合）**：作为正在练习恋爱沟通的用户，我想在 App 内直接阅读 17 万字长篇并在关键节点"替换男方回复"介入练习，以便把"读小说"变成"动手练"，而不是只能看不能动。

- **US2（智能升级·阶段）**：作为经常忘记手动切阶段的用户，我想让 AI 根据对话内容自动判断当前关系阶段，以便阶段判断更贴合实际对话进展，同时保留手动覆盖的能力以便我纠正误判。

- **US3（智能升级·教练基准）**：作为认真训练的用户，我想让教练评分更准、不再虚高，以便我的训练日志趋势能真实反映进步，而不是被鼓励性高分麻痹。

- **US4（体验·移动端）**：作为通勤路上用手机练习的用户，我想在聊天界面和教练建议之间一键切换而不需要长距离滚动，以便我在手机上也能高效完成一轮"发消息 → 看评分 → 看 ABC 建议"的闭环。

- **US5（角色扩容·剧本）**：作为遇到具体困境的用户，我想直接进入一个预设情境（如"她突然冷淡""被放鸽子""第一次邀约被拒"）开始练习，以便我针对真实场景快速训练而不是从零构建上下文。

## 三、需求池

### P0（Must have）

#### P0-1 长篇章节数据层与索引
**描述**：建立长篇 10 章的结构化索引，供前端按章节/小节/复盘点读取。需解析 markdown 原文，提取对话行（`**我：**`/`**夏紫桐：**`）、叙述段、`### 恋爱大师复盘 N`（含意图/好处/风险/修正四要素）。
**实现约束**：原始 markdown 在 `long-simulation/` 目录；为避免运行时解析开销与跨平台路径问题，建议构建时（或首次启动时）生成一份 `public/js/long-content-index.js`（纯数据模块，零依赖），包含每章的章节元信息 + 小节定位 + 复盘点定位。不引入 markdown 解析 npm 包。
**验收标准**：
- 10 章全部可被索引，每章的复盘点数量与原文一致（如第1章5个）。
- 索引数据体积可控（仅定位信息 + 复盘全文，对话原文按需从 server 读取，避免一次性塞进前端）。
- 零新增 npm 依赖。

#### P0-2 章节阅读视图
**描述**：在 App 内新增"长篇阅读"入口，支持浏览 10 章目录、进入单章阅读、对话与叙述分行渲染、复盘点折叠展示。
**验收标准**：
- 可从主界面进入长篇阅读视图，看到 10 章列表（含章节标题与简介）。
- 进入单章后，对话以仿微信气泡样式呈现（我/夏紫桐区分左右），叙述段以浅色块呈现，复盘点以可折叠卡片呈现并高亮四要素。
- 阅读位置（章+小节）持久化到 localStorage，下次进入可续读。
- 阅读视图不调用 LLM，纯前端渲染，离线可用。

#### P0-3 关键节点介入练习
**描述**：在长篇阅读中，标记可介入的对话节点（每个复盘点对应的男方发言处）。用户在该节点点击"介入练习"，进入一个独立练习面板：显示节点前文上下文 → 用户输入自己的男方回复 → AI 基于上下文 + 夏紫桐角色设定生成女方反应 → 展示用户回复 vs 原著男方回复的对照，以及原著复盘要点。
**验收标准**：
- 每章至少在复盘点对应的男方发言处提供介入入口（第1章≥5处）。
- 介入练习调用 `/api/chat`，prompt 复用夏紫桐角色设定 + 节点前文，要求模型只生成"夏紫桐的下一句反应"，不生成 ABC/评分（与主聊天模式区分）。
- 对照视图清晰展示：用户回复 / 原著男方回复 / 原著女方后续反应 / 恋爱大师复盘要点（意图/好处/风险/修正）。
- 介入练习记录可保存为一条训练日志（标注来源章节+节点）。
- 介入练习不得生成操控性或越界话术（复用现有 prompt 中的反 PUA 约束）。

#### P0-4 阶段自动判断（状态机 + 手动覆盖）
**描述**：新增 AI 阶段判断能力。每轮对话后（或用户主动触发"判断阶段"时），AI 基于完整对话历史输出当前关系阶段（从现有7阶段中选一），并写入阶段选择器。手动选择作为覆盖项保留：用户手动改动后，以手动值为准直到用户主动重新触发自动判断。
**验收标准**：
- 阶段判断复用现有 `/api/chat`，输出限定为7阶段枚举值之一 + 一句判断理由。
- 自动判断结果与手动选择在 UI 上有视觉区分（如"自动"徽标），用户可一键采纳或手动改。
- 手动覆盖优先级高于自动判断，且覆盖状态持久化。
- 判断失败（模型超时/格式错误）时静默保留上一阶段，不阻断对话，并在控制台记录。
- 现有手动阶段下拉框不删除，作为兜底与覆盖入口。

#### P0-5 教练评分基准校准
**描述**：基于长篇语料建立教练四维评分基准，校准 `coach.js` 的启发式打分，减少虚高。具体：从长篇"恋爱大师复盘"的"风险/修正"标注中提取负向样本基线，从"好处"标注中提取正向样本基线，调整 `buildCoachScore` 各维度的基准分与扣分项权重。
**验收标准**：
- 长篇中"被复盘指出有风险"的男方回复样本，本地启发式评分在对应维度（多为边界感/自然度）不得高于 65。
- 长篇中"被复盘肯定"的男方回复样本，本地启发式评分按 `docs/coach-calibration-baseline.md` 的逐条阈值通过；强信号样本不低于 75，单一或较弱信号样本使用已记录的 60/65/70 校准阈值。
- 提供 `test/` 下的基准校验用例（≥20 条样本覆盖四维），可被 QA 回归。
- 校准不改变 `buildCoachScore` 的函数签名，保持向后兼容。
- 评分虚高问题改善可量化：现有"无越界词即边界感≥78"的基线被下调至更合理的阈值。

#### P0-6 Prompt 层独立模块
**描述**：把 `app.js` 中散落的 prompt 构建函数（`buildSystemPrompt`、`buildRelationshipCoachSkillPrompt`、`buildGenerationTaskPrompt` 等）抽离到独立文件 `public/js/prompts.js`，作为纯函数模块，便于版本管理与迭代。
**验收标准**：
- `app.js` 不再直接定义 prompt 字符串拼接逻辑，改为从 `prompts.js` import。
- 抽离后行为完全等价（同一对话历史产生相同 prompt），无功能回归。
- `prompts.js` 内函数命名清晰、单一职责，并附 JSDoc 注明输入输出与版本号。
- 零新增依赖。

### P1（Should have）

#### P1-1 经典复盘对照
**描述**：在主聊天训练模式下，当用户的训练场景与长篇某章节主题接近时（如"第一次邀约被拒"对应第3章），在教练层提供"对照长篇复盘"入口，展示对应章节的恋爱大师复盘要点，供用户参照。
**验收标准**：
- 提供基于关键词/阶段的复盘对照映射表（7阶段 × 长篇10章主题）。
- 对照入口在教练面板呈现，不强制弹出，用户主动点击查看。
- 对照内容标注出处章节。

#### P1-2 移动端 Tab 切换布局
**描述**：重构移动端（≤720px）布局，从"三栏垂直堆叠"改为"底部 Tab 切换"（聊天 / 教练 / 角色），让用户在手机上一键切换面板而非长距离滚动。
**验收标准**：
- ≤720px 时，主视图只显示当前激活 Tab 的面板，其余隐藏，底部固定 Tab 栏切换。
- 默认激活"聊天"Tab；用户发送消息后，若教练面板有新内容，Tab 栏"教练"项出现未读提示点。
- 聊天 Tab 内的输入框在手机键盘弹起时保持可见（不软键盘遮挡）。
- 现有桌面端三栏布局（>1050px）不变；1050–720px 的两栏布局保留现有行为。
- 不引入 UI 框架，纯 CSS + 少量 Vanilla JS 实现。

#### P1-3 场景化训练剧本
**描述**：提供预设情境剧本库（如"她突然冷淡""被放鸽子""第一次邀约被拒""暧昧期查户口感"等），每个剧本给定：情境描述、女方开场前文、推荐阶段、推荐角色、教练关注维度。用户选择剧本后，自动加载前文与设定，直接进入练习。
**验收标准**：
- 首批提供 ≥5 个剧本，覆盖初聊/邀约/冲突/边界等典型场景。
- 每个剧本的情境描述不包含操控话术或"如何反制对方"的表述，聚焦"如何真实、有分寸地沟通"。
- 剧本数据为纯前端静态数据（`public/js/scenarios.js`），零依赖。
- 选剧本后自动设置阶段与角色，用户可改。

#### P1-4 长篇角色扩容·夏紫桐内置化
**描述**：把夏紫桐作为第 4 个内置角色加入 `config.js`，不止于 `starterMessages`，需有完整背景、兴趣、边界、阶段行为提示。其设定以 `long-simulation/02_夏紫桐人设.md` 为准。
**验收标准**：
- `builtInPersonas` 新增 `zi`（夏紫桐），字段结构与现有三位角色一致（id/name/avatar/meta/tags/logic/systemRole/starterMessages/defaultGoal/localHerReply）。
- `systemRole` 凝练夏紫桐核心特质（观察细、反应不快、渴望亲密又警惕被分析、抑郁症设定不被浪漫化、有自己的拒绝权）。
- `starterMessages` 取自第1章开篇的重新联系场景，自然衔接。
- 角色卡明确标注其设定边界（不诊断、不浪漫化病情、不把恋爱当治疗）。
- 可在角色切换下拉中选用。

### P2（Nice to have）

#### P2-1 介入练习的复盘生成
**描述**：介入练习中，除对照原著复盘外，额外调用 AI 为"用户自己的回复"生成一份模拟复盘（同样输出意图/好处/风险/修正四要素），与原著复盘并排展示。
**验收标准**：可选开关；生成内容遵守反 PUA 约束；失败时静默退化为只展示原著复盘。

#### P2-2 阶段判断置信度与过渡提示
**描述**：阶段自动判断时附带置信度（高/中/低），低置信度时提示用户手动确认；阶段发生跃迁时（如从"第一次邀约"跳到"确定关系"）给出过渡合理性提示。
**验收标准**：置信度展示在判断理由旁；不合理跃迁给出"对话似乎尚未支撑该阶段，建议保留上一阶段"的提示而非自动采纳。

#### P2-3 Prompt 版本管理
**描述**：`prompts.js` 支持 prompt 版本号，并在请求中携带版本号便于日志回溯与 A/B。
**验收标准**：每个 prompt 函数有 `version` 字段；训练日志可选记录 prompt 版本。

#### P2-4 长篇阅读进度仪表盘
**描述**：在长篇阅读入口展示总体阅读进度（已读章数 / 复盘点已对照数 / 介入练习次数）。
**验收标准**：进度数据来自 localStorage；仅展示，不强制任务化。

## 四、UI 设计要点

### 4.1 长篇阅读视图（方向①核心）

新增顶部入口"长篇教材"（与"导出/重置"同区）。进入后：

```
┌─────────────────────────────────────────────┐
│  ← 返回训练台        长篇教材 · 夏紫桐系列      │
├──────────────┬──────────────────────────────┤
│ 章节目录      │  第一章：重新联系与重新认识      │
│ ▸ 第1章 重新联系│  ─────────────────────────   │
│ ▸ 第2章 稳定联系│  [周一 22:18]                │
│ ▸ 第3章 低谷边界│  我(气泡右): 夏紫桐，好久不见… │
│ ▸ 第4章 喜欢出现│  夏紫桐(气泡左): 好久不见…    │
│ ▸ ...         │  我(气泡右): 偶尔，最近公司…   │
│               │  ─────[可介入节点]─────        │
│               │  ▼ 恋爱大师复盘 1  (折叠)      │
│               │     意图/好处/风险/修正         │
└──────────────┴──────────────────────────────┘
```

- 左侧目录章数持久化已读状态（已读章打勾）。
- 对话行用气泡区分我/夏紫桐，叙述段用浅色引述块。
- 复盘点默认折叠，点击展开四要素。
- "可介入节点"在男方发言气泡上出现小按钮「介入练习」。

点击「介入练习」后以模态/抽屉展开：

│                                                        │

│ 你的回复      vs  原著男方回复                          │

### 4.3 阶段自动判断（智能升级）

现有阶段下拉框上方新增一行：

```
当前阶段: [刚加微信后的第一晚 ▾]   [🤖 自动判断]
         (自动 · 置信度中)          ↑ 点击触发AI判断
```

- 自动判断结果写入下拉框，并显示"自动 · 置信度X"徽标。
- 用户手动改下拉框后，徽标变为"手动"，自动判断暂停采纳，直到再次点"自动判断"。

### 4.4 移动端 Tab 布局（≤720px）

```
┌─────────────────────────┐
│  HeartFlow   [检查] [导出]│  ← 顶栏精简
├─────────────────────────┤
│                         │
│   (当前 Tab 内容区)      │  ← 仅显示激活Tab
│   聊天 / 教练 / 角色     │
│                         │
├─────────────────────────┤
│ [💬聊天] [📋教练●] [👤角色]│  ← 底部固定Tab栏
└─────────────────────────┘
```

- 底部 Tab 栏固定，"教练"上的●为未读提示（有新评分/ABC时出现，查看后消失）。
- 桌面端（>1050px）保持现有三栏，不显示 Tab 栏。

### 4.5 场景化剧本选择

在角色面板"训练阶段"上方新增"情境剧本"折叠区：

```
▼ 情境剧本
  ○ 她突然冷淡（推荐阶段：暧昧推进）
  ○ 第一次邀约被拒（推荐阶段：第一次邀约）
  ○ 被放鸽子后如何沟通（推荐阶段：第一次约会后）
  ○ ...
  [加载剧本]
```

加载后自动设置阶段、角色、前文，用户直接开始练习。

## 五、待确认问题

> 以下需交付总监或项目作者澄清，影响实现路径与优先级。

1. **长篇内容加载策略**：10 章 markdown 合计约 90 万字符。是构建期生成静态索引 + 按章懒加载（推荐），还是由 server 新增 `/api/long-content/:chapter` 端点按需读取原文？后者改动 server.js，但能彻底避免前端打包体积。倾向后者，需确认是否允许在 server.js 新增只读端点（仍零依赖）。

2. **介入练习的上下文长度**：单次介入需把节点前文喂给模型。一个复盘点前文可能数百到上千字。是否接受按"小节"截取前文（而非整章）以控制 token？还是要求完整前文以保证连贯性？

3. **阶段自动判断的触发时机**：是每轮对话后自动判断（增加每次请求的 LLM 调用，成本翻倍），还是仅在用户点击"自动判断"按钮时触发（更省成本但不实时）？倾向后者 + 提供开关。

4. **教练基准样本的归属**：校准 `coach.js` 所需的"长篇正/负向样本"是手动标注抽取（准确但耗时），还是用脚本按复盘段落结构半自动提取（快但需人工复核）？首批建议人工抽取 20-30 条。

5. **夏紫桐角色的边界声明强度**：夏紫桐有抑郁症设定。在角色卡上是否需要更显眼的"本角色涉及心理健康议题，模拟不构成医疗建议"提示？还是融入 systemRole 即可？

6. **移动端 Tab 的桌面断点**：是否接受 ≤720px 才启用 Tab 布局（现有断点），还是平板尺寸（≤1050px 两栏）也改为 Tab？倾向保留 1050px 两栏、仅 720px 以下改 Tab，需确认。

7. **剧本数据维护**：场景化剧本后续是否需要用户自建/导入，还是仅维护官方预设？本次 P1 仅做官方预设，需确认范围。

8. **prompt 抽离的回归验证基线**：抽离 `prompts.js` 后如何验证"行为等价"？是否有现成的对话 fixture 可比对输出？若无，需 QA 补一轮 prompt 快照对照。
