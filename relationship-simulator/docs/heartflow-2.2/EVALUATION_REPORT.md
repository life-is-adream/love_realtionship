### 本轮发现并修复的差异

1. 首次全量对比出现 12 处排序差异（例如 `ret-cand-020` 第 5/6 位 `176,179` 与 `176,12` 互换），均为相邻名次、集中在候选 query 上。定位为 C 端文档长度口径少算两个连接空格：Node 对普通文档使用 `chars(title + " " + goal + " " + body)`，C 误用了不含空格的长度。修正后 800/800 一致。
2. 弃答路径首次实现时 C 进程崩溃（0xC0000005），原因是 `requested/effective` 在门禁块之后才赋值。将赋值上移到 limit 校验后即恢复。

这说明：**只有把评分公式的每一个字符口径、每一个分支的初始化顺序都对齐，才能谈“双端一致”**。

`quality/datasets-2.2/candidate-independent/retrieval.json`：60 条域内场景化问法 + 5 条域外问法，相关性由单人按课程标题挑选，仍是 `reviewed_by_human: false`。

| 模式 | Recall@5 | MRR@5 | nDCG@5 | 引用错误 | 域外弃答率 | P50 | P95 |

这是本轮唯一有信息量的对比：在这批问法上 **hybrid > semantic > bm25**（R@5 34.7% / 33.6% / 31.1%），说明概念扩展与混合排序确实带来提升，而不是靠 query 与课程文本同源刷分。

但 31–35% 的绝对值表明：**实际用户问法与课程标题之间存在明显语义鸿沟**，这正是需要真实 embedding 与人工标注才能继续推进的部分。该集标签只按标题挑选、未经双人复核，绝对值仍不可作为验收依据。

### 本轮修复的语义漏判

候选集中 5/300 条把「还没有准备好见面。」判为 `OBSERVE`（应为 `DE_ESCALATE`），原因是词表只有「还没准备好」。已在 `DECLINE`（Node）与 `V2_DECLINE_TERMS`（C）补入「还没有准备好」，并新增 3 条固定用例（`test/fixtures/semantic-cases.json` S13b/S13c/S13d）作为回归；候选集 300 条现为 100.0%。

该修复基于**候选集**（非冻结 test），旧 test 未被用于本轮词表调整。

## 6. 失败案例清单

1. 双端一致性首轮 12 处排序差异：已定位并修复（文档长度口径）。
2. 域外查询 21 条仍有 1 条未弃答：「更换手机屏幕」因包含领域词「手机」而被判定为课程域内。启发式门禁的固有局限，记录不隐藏；若要根治需要真正的意图分类器。
3. 语义候选 5 条「还没有准备好」漏判：已修复并加回归用例，候选集 300/300 通过。
4. E2E「用户主动保存规则分数并显示成长图」失败：根因是前端 `normalizeAssessment` 只接受 `rubricVersion === "1.1.0"`，而服务端五维量表已升为 `2.1.0`，导致保存被拒。已改为版本白名单 `["1.1.0","2.1.0"]` 并新增单元测试；现 `scripts/e2e-heartflow-v2.mjs` **30/30 通过**（日志 `quality/reports/e2e-heartflow-v2-2.2.log`）。
5. 2.1 遗留的 2 条语义泛化失败（`可以，一起去`、`照现在的方式相处就行`）状态不变，需人工标注确认口径。

## 7. 方法学边界

- 历史 dev/test 已曝光；候选集标签为 AI 建议；两者都不能代替独立人工标注。
- 候选检索 query 与相关课程同源（课程目标改写），R@5 99.4% 没有信息量；独立场景集只是去掉了同源偏差，标签仍为单人按标题判定。
- 引用有效只表示行号与原文一致，不表示该段落是最佳教学段落。
- 没有真实 embedding、没有重排器、没有人工自然度与角色一致性盲评。
- 弃答门禁是词表 + 阈值启发式，不是分类器，存在漏判（1/21）与潜在误拦风险。
- 没有使用任何真实用户聊天记录或 `.env` 密钥。
