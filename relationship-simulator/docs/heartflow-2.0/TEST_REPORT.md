## 失败和修复

- 首次全量运行时，新增日期校验触发项目的 UTC 日期键约定检查；调整为逐字段校验日期后，完整 `npm test` 通过。
- 将旧 C/Node 对照接入新测试时，Windows 子进程默认编码与 UTF-8 输出读取不一致；对该合成测试子进程设置 UTF-8 后接口测试通过。
- 被拒绝后的练习、否定句「不再联系」和模型输出无效 JSON 均增加了针对性测试。上述通过仅覆盖测试中的表达，不能证明所有中文语义均正确。
- 审计合成集复现的「不要给我发消息」「别找我」「从来没有威胁你」等拒绝/否定误判已修复：否定判断只回溯同一分句，并把「不过/但是」视为转折边界；16 例回归集在 C 与 Node 上一致。
- 预设角色此前只按分支输出固定句；现在会区分施压、共情、留出选择空间和提问，并引用用户刚说的短句，拒绝分支仍保持明确结束。
- 预设角色已加入由历史累积的多轮状态：连续施压提高 `tension`，达到 3 时结束；道歉/共情/留出空间降低 `tension` 并记录 `repair`。状态由客户端随请求回传，服务器不持久化，C/Node 与接口测试一致；真人盲评和长期一致性仍未验证。
- 评分证据此前可能只是一个关键词；现在引用命中词所在的完整分句，短于 4 字或不足一个分句时标记为证据不足、不计分。模型复核同样拒绝单字引用。
- 备份不再包含载入失败的隔离原始串；恢复中途写入失败会回滚已写入的键。
- 分析页三路请求改为各自完成后立即渲染；慢课程或单路失败不再拖住已完成的分析与回复。
- 审计发现旧接口可被局域网访问、CORS 还会回显私有网段来源；现在 C 与 Node 默认只监听 `127.0.0.1`，旧接口同样校验页面来源，需显式配置 `HF_BIND_HOST` 才放开局域网。随后补上 Host 校验：外部域名（DNS rebinding）访问页面或接口一律 403。上述通过不构成公网加固、多用户隔离或 TLS 证明。
- 课程推荐由标题/目标词面匹配改为读取正文的 BM25，并补上默认 3 条、`limit` 1–10 的参数校验与 C/Node 对照；随后加入通用领域同义扩展。基线从 64.1% 提到 65.1% Recall@5，提升有限；这不是“检索已达标”，而是下一轮语义检索的起评分。
- 语义基线暴露出规则对新改写仍偏保守：例如“我不想现在见面，但以后可以再聊”被判为 OBSERVE，而人工预期是 DE_ESCALATE。本轮只记录基线，没有继续堆叠规则。

## 尚未运行或无法据此通过的检查

- 没有使用真实视觉模型、真实 OCR 截图、真实在线语音识别、真实麦克风或侧车音频播放；尚不确定现有账号配置的模型是否支持图片。
- 没有 200 组 OCR 标注样本、150 个经人工核验的关系案例、100 组回复盲评、100 个课程检索标注问题、30 个模型角色场景或 100 份人工评分对照；原任务书的 F1、Recall@5、自然度、评分误差和角色遵循率均未计算。
- 没有 100 组跨用户/跨账号隔离测试。当前系统没有独立用户账户或服务端资源归属，不能宣称具备这些保障。
- 浏览器取消仅验证迟到结果不会写回页面，未验证上游模型真实停止；未实测 45 秒超时的完整时长、真实上游网络失败和供应商日志删除。假上游 HTTP 503 的错误响应已测。
- 对输入注入、无效 JSON、引用原文和拒绝信号做了少量合成测试，未对所有模型输出、课程内容投毒或复杂语言攻击做完整对抗评测。
- 没有本次新版本的真人临床、沟通能力或关系结果评估；规则分数不代表现实成功率。

## 复现

在项目根目录：

```powershell
npm test
python heartflow-c/tests/v2-smoke.py heartflow-c/hf.exe
node scripts/e2e-heartflow-v2.mjs
.\heartflow-c\hf.exe tts selftest
```

浏览器测试需要 Chrome 或 Edge（可通过 `CHROME_PATH` 指定），会启动临时 C 服务和本机假模型。Windows 下重新构建：

```powershell
cd heartflow-c
& 'D:\Git\bin\bash.exe' ./build.sh hf-v2-build.exe
```

其他机器的 Git Bash 和 C 编译工具路径可能不同，需使用本机对应工具。不要将测试命令中的假模型结果当成真实供应商结果。
