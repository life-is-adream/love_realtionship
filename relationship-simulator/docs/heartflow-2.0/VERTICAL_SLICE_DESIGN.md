# 最小闭环与扩展实现

## 用户路径

1. 打开「关系分析」，粘贴聊天或用事件叙述；也可在同意图片发送后导入截图。
2. 在列表中更正说话人、顺序、时间和文字；无时区或无效时间只保留原文，不参与时间计算。
3. 可直接生成三条快速回复；也可选择完整分析，本机并行生成输入原文与来源、可能解释及未知、决策参考、课程推荐和三种回复。课程推荐只接受真实索引和文件。
4. 选择一条回复或直接按问题开始练习；可改场景、目标、难度和分支。预设角色本地运行；模型角色需本次同意。
5. 评分逻辑独立读取用户练习文本，显示可定位片段、启发式评分与不适用/证据不足项；可修改后再次练习。模型复核是另一次明确同意的请求。
6. 用户自选或依据最近的可评分维度生成每周计划。需要长期保存时，单独选择关系档案并开启授权，手动填写复盘或主动保存练习规则评分，按同场景、同维度查看趋势。

## 实现分层

`public/modules/relationship-flow/flow.js` 处理界面与临时状态；`heartflow-c/src/server/v2.c` 校验和处理导入、分析、模板、课程匹配、场景、评分、每周计划、语音停顿及图片模型适配；`server/v2.js` 是 Node 参考。`public/modules/core/relationship-cases.js` 与 `weekly-plan.js` 控制浏览器内可保存结构。

分析事实类型为 `user_supplied_text`，是用户提供的原文而非经独立核实的现实事实。假设的 `support_ids` 指向输入消息，不允许转换为事实。课程返回实际课程编号与标题，不允许模型编造链接。评分证据引用用户练习消息，模型引用须逐字包含在对应原文中；评分理由本身仍可能有误。

## 超时与撤销

模型文本请求在页面等待 45 秒后中止等待；截图服务有较长上游超时。用户取消或更改输入后，旧结果不能覆盖新界面。中止浏览器等待不保证 C 服务已发送的请求或模型供应商的处理停止；在服务侧应继续补充真正的请求取消、限流和留存控制。

## 成长与隐私

档案默认不授权保存复盘；用户手动保存的观察、假设、结果分字段，评分只保存规则版本、场景、日期和分值，不保存练习原文。双人问题在同一浏览器页面内用双方口令封存，双方同意后显示；不是独立账号。语音输入由浏览器负责识别，可能经过浏览器服务商；HeartFlow 的停顿接口只收数值摘要。

这条路径已用合成数据和本机假模型执行，尚不能证明真实 OCR 精度、真实语音质量、专业评分一致性或用户能力改善。
