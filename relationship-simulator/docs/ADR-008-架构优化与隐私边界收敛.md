# ADR-008: 架构优化与隐私边界收敛（Lovekey 启示落地）

## Status
Accepted（2026-08-03）

## Context

基于 Lovekey键盘 产品/设计调研的启示（亲密度可视化、隐私信任设计、本地语义检索），
以及一次全量架构普查（284 测试基线 / 41 模块 0 循环依赖），发现四个高价值低风险的
优化点：

1. **服务端 7 个模块零单测**，llmProxy 无重试、CORS 硬编码 `localhost:3000`、请求体超限
   被误报为 400（应为 413）、上游错误不语义化。
2. **隐私脱敏边界分散**：`redactSensitiveText` 只接在回放增强路径（且该路径被禁用），
   其余 4 条出站路径（主聊天 / 行动计划 / 阶段判断 / 发送前测验 / 介入练习）都汇聚在
   `api-client.js callLLM` 单一出口，但该出口零脱敏。
3. **教材检索是纯关键词 BM25**，无语义增强；且 33,384 行索引在 app.js 与
   render-learning.js 各构建一次。
4. **app.js 内联 action plan prompt**，未复用 prompts.js 纯函数模块。

## Decision

按「最小可审查改动 + 测试兜底 + 零新依赖」原则，做四项改动：

1. **服务端韧性**（server/llmProxy.js、staticServer.js）：
   - `fetchWithRetry`：瞬时 5xx / 网络错误重试 1 次（4xx、超时不重试，注入式 `fetchImpl` 便于测试）。
   - CORS 改为 `resolveCorsOrigin`：只放行 localhost / 127.0.0.1 任意端口，外部来源回落默认源。
   - 请求体超限返回 **413**（`RequestBodyTooLargeError`，区别于 400 invalid_json）。
   - 上游 ≥400 错误语义化为 `upstream_error` + `upstreamStatus`。
   - 新增 `test/server-modules.test.mjs`（21 例）补齐服务端零覆盖缺口。

2. **隐私边界收敛**（新增 `public/modules/core/privacy.js`）：
   - `redactSensitiveText` 从 replay.js 抽到共享模块（replay.js 保留 re-export 兼容）。
   - 新增 `sanitizeOutboundMessages`，在 `callLLM` 发送前对所有消息统一脱敏（邮箱/网址/电话/长编号），
     覆盖全部出站路径；返回 `redactionHits` 供信任提示使用。
   - 新增 `test/privacy.test.mjs`（4 例）。

3. **检索语义增强**（textbook-search.js）：
   - 新增纯函数 `bigramJaccard`（字符 bigram Jaccard，确定性、零依赖），
     在 `rankTextbookResult` 中作为排序加分（上限 8 分）。
   - **关键发现**：中文同义改写必然换字（“很忙”→“忙”），bigram 相似度通常 <0.45，
     因此**不做独立语义召回通道**（会变成死代码），语义召回仍由 SYNONYM_GROUPS 承担，
     bigram 只负责在关键词命中相近时拉开排序差距——诚实空态契约（无证据不编造）不受影响。
   - 新增测试 4 例。

4. **app.js 瘦身**：
   - action plan 内联 prompt 迁移为 `buildActionPlanPrompt`（prompts.js 纯函数），行为不变。
   - 新增 `content/textbook-index.js` 共享单例 `getSharedTextbookIndex`，
     app.js 与 render-learning.js 改为复用同一索引，消除双份构建。

## Consequences

**变容易**：
- 服务端有了回归保障（21 例），llmProxy 对瞬时故障不再直接 502。
- 所有出站内容在唯一出口统一脱敏，未来加新的模型调用自动获得隐私保护；
  前端可基于 `redactionHits` 展示“本次调用已脱敏 N 处”的信任提示。
- 教材检索在关键词命中相近时排序更贴合语义，且不会误召回（诚实契约保持）。
- prompts.js 成为唯一 prompt 来源，app.js 更薄。

**变困难 / 代价**：
- `callLLM` 返回对象多了一个 `redactionHits` 字段（向后兼容，旧调用方忽略即可）。
- 服务端对上游 4xx/5xx 的错误响应结构从“原样透传”变为统一 `upstream_error` 包装，
  依赖旧响应形状的外部脚本需适配（本项目前端已兼容）。
- 检索排序分数因 bigram 加分略有变化（确定性可复现，但数值非语义含义）。

**验证**：全量测试 315/315 通过（基线 284 + 新增 31）；`check:circular` 43 模块 0 环；
服务启动冒烟 `/api/health`、`/api/long-content/1` 正常。

## 补充：Lovekey 启示的 UI/功能落地（2026-08-03 晚，全量测试 333/333，46 模块 0 环）

在架构优化基础上，把 Lovekey 调研的设计启示落成 5 个前端/服务端功能：

1. **信任提示条**：`callLLM` 返回的 `redactionHits` 由 `formatRedactionNotice` 格式化为
   「🛡 已脱敏 手机号 1 处、邮箱 2 处，未发送原始信息」，显示在 API 状态区（`#privacyNotice`）。
2. **关系进度可视化**：`render/stage-progress.js` 纯函数 `buildStageProgress` 把 7 训练阶段映射为
   进度条 + 节点解锁动画（`#stageProgress`），随阶段选择/自动判断实时刷新。
3. **教练悬浮快速呼出**：`render/coach-float.js` 纯函数生成悬浮球面板（A/B/C + 四维评分），
   聊天区右下角 `✦` 按钮一键呼出（`#coachFloat`），减少面板切换（Lovekey 悬浮球三步流启发）。
4. **真诚度/语气强度滑块**：`prompts.js` 新增 `buildToneGuidance` 纯函数，UI 两个 range 滑块
   （`#sincerity` / `#toneIntensity`）注入 `buildSystemPrompt`，对抗油腻、强化真实沟通定位。
5. **联网搜索（默认关闭）**：`server/searchProxy.js` 新增 `POST /api/search` ——
   `SEARCH_ENDPOINT`/`SEARCH_API_KEY` 未配置时返回 503 `search_disabled`；白名单权威域名
   （`SEARCH_ALLOWED_DOMAINS`，默认 edu.cn/gov.cn/who.int/apa.org 等）过滤；审计日志只记查询词；
   **只接收查询词、绝不接收对话内容**。前端悬浮面板「🔍 联网查依据」按钮调用，展示白名单结果。

**未做（明确保留）**：
- 联网搜索仍需用户配置真实搜索服务端点/Key 后才可用（当前默认关闭）。
- 真向量检索（embedding）在零依赖约束下不可行，bigram 为当前上限。

## 未做（明确保留）

- 联网搜索（Web Search / Agentic RAG）：见 ADR 上下文——项目隐私优先、本地优先，
  联网与“不上传教材”冲突，仅设计了白名单 + 默认关闭 + 审计的路线，本轮不实现。
- 向量检索（真 embedding）：零依赖约束下不可行，bigram 为当前零依赖上限的近似方案。
