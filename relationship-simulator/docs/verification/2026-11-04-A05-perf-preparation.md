## 1. 一条必须先说的结构性事实

`server/llmProxy.js:85` 把 `stream: false` 写死，全仓没有任何增量正文路径（grep `stream` 只命中这一行）。
因此规范 §2.1 的 t1（首个非空正文完成首字符可见 DOM 更新）在当前架构下**只能等于 t2**：

- `TTFC P95 ≤ 6s`、`Good-turn ≥ 95%` —— 现在就能量；
- `TTFV P95 ≤ 2s` —— **不可能靠调参达标**，它是 P2（SSE 快速角色回复链）的验收项，不是本轮的。

报告生成器把这条写进了判定：没有 paint 口径或没有流式时，TTFV 一律输出「未测（原因）」，
不允许输出一个数字假装量过。

## 2. 彩排（0 次请求）抓到的三个真缺陷

建量具时在真实页面里用假 `callLLM` 跑了一遍，三个都是不跑就发现不了的：

1. **永久挂起**：`t2` 原本等 `requestAnimationFrame`。受控浏览器窗口是 `visibilityState=hidden`，
   rAF 在该页**永远不触发**，`await` 直接卡死 → 一次 15s 工具超时。改成「rAF + 3s 兜底超时」，
   兜底路径标 `t2Source=frame-timeout` 并在报告里点名（这种样本的可见时刻不可信）。
2. **隐藏标签页不能做计时测量**：把兜底定时器去掉后仍然量到 ~950ms，而假响应只有 200ms ——
   隐藏页里**所有** `setTimeout` 都被钳到 ~1s。结论：后台跑 = 一批系统性偏胖的假数字，
   于是**取消**了「只取 TTFC 也行」的 allowHidden 降级模式，改为可见性闸门直接拒绝（且在发出任何请求之前拒绝）。
3. **旧模块缓存**：改动探针后页面仍执行改动前的版本（动态 import 没带本仓的 `?v=` 缓存串），
   让我一度以为护栏没生效。带 `?cb=` 重新 import 才看到正确行为。这是工作区老坑（`?v=` 双实例）的又一形态。

最终彩排结果：`llm_calls=3`、`hygiene.clean=true`、`leftovers=0`、`localStorage` 键数前后一致。

### 这组数字的含义（比「未达标」更重要）

1. **问题不是中位数，是长尾。** P50 2.3s 离 6s 很远，但 10% 的样本落在 6s 外，其中一条 31.4s ——
   与 A-03 抽样里观察到的 40.4s 同源。这类长尾由上游波动支配。
2. **SSE 治不了这个 SLO。** P2 的流式改善的是 TTFV（首字可见），而 A-05 挂在 TTFC/Good-turn 上：
   正文到齐的时刻不会因为分块到达而提前。所以「做完 P2 就达标」是错的预期 ——
   这正是 P0 验收记录里那条预测（TTFC P95≤6s 大概率不由 SSE 决定）被证实。
3. **能真正改善 TTFC 的是**：(a) 上游换更低方差的供给或做双发竞速（要花双倍钱，需单独批准）；
   (b) 按规范 §2.3 把「6 秒提示仍在生成 / 8 秒给继续或取消」做成真交互，让用户侧体验不再被长尾卡死；
   (c) 接受把 A-05 记为「上游受限、本地链路无过错」并在版本声明里不写「6 秒已达成」（规范 §1.2 的口径）。
4. **基线可复用**：40 条集合固定且样本已落盘（`2026-11-04-A05-perf-samples.json`），
   P2 之后同集合重判只需再花一次 40 请求，或用浏览器口径补上 t1 —— 报告侧改动一律零成本重出。

### 一处必须记下的自我更正

生成的报告模板最初硬印「方法：浏览器内 performance.now() + MutationObserver 首字可见」，
而这一轮实际是 Node 往返 —— **报告声称用了它没用过的量法**。已改为从样本口径推导
（`describeMethod`，混口径时两边都写），并加测试钉住；报告用已落盘样本离线重出，0 次新增请求。
这类「证据文案与实际做法不一致」和前面「0 分母报成 0%」是同一族缺陷，只是这次发生在文字层。
