# HeartFlow 训练平台增量设计

日期：2026-07-16  
范围：消息优化器 2.0、对话回放分析、社交信号解读训练、每日微训练、成长路径与能力画像、教材检索与引用、时机感评分

## 1. 目标与成功标准

本次增量把 HeartFlow 从“生成一条回复并评分”升级为可持续的沟通训练闭环：

```text
输入消息/真实聊天
  → 信号与时机分析
  → 多版本优化或回放复盘
  → 发现短板
  → 每日专项练习
  → 成长画像
  → 长篇教材依据
```

成功标准：

- 用户可以同时看到原文、低压力版、主动推进版及修改理由。
- 用户可以练习判断“兴趣、礼貌、疲惫、边界、收尾、不确定”等多种社交信号。
- 时机评分只给出可解释的沟通建议，不制造“必须等待多久”的机械规则。
- 用户粘贴脱敏聊天记录后，可以得到双方投入、追问、冷却、边界和误读分析。
- 每日任务与用户当前短板相关，并能记录完成情况。
- 成长画像能够区分本地评分、模型评分、介入练习评分和校准前历史数据。
- 当前问题可以检索到长篇教材中的相关章节和复盘点；无高相关内容时明确显示无结果。
- MiMo 失败时所有核心功能仍有本地退化方案。

## 2. 范围与非目标

### 2.1 本次范围

分三阶段交付，但三阶段共享同一套训练结果和持久化结构。

#### 阶段一：即时沟通闭环

- 消息优化器 2.0
- 社交信号解读训练
- 时机感评分

#### 阶段二：训练与成长闭环

- 对话回放分析
- 每日微训练
- 成长路径与能力画像

#### 阶段三：教材智能引用

- 教材检索与引用
- 七个功能的统一联动
- 统一错误处理和回归测试

### 2.2 非目标

- 本次不做账号系统、云端同步和情侣双向模式。
- 本次不做 UGC 角色市场和公开社区。
- 本次不引入 React、Vue、Chart.js 或 Markdown 解析 npm 包。
- 本次不把真实聊天原文默认上传到模型或长期持久化。
- 本次不把社交信号转换成单一“她喜欢你多少分”。

## 3. 设计原则

- 延续 Node.js + Vanilla JS + ES Module + 零新增依赖。
- `app.js` 只负责页面控制、状态编排、模型调用和 DOM 更新，业务逻辑放入可测试模块。
- 本地规则优先，模型增强；所有结果标注 `source` 和 `confidence`。
- 任何判断都要提供证据和不确定性，不把礼貌、疲惫或收尾误判成暧昧。
- 用户的真实聊天记录默认本地处理；发送给 MiMo 前必须有明确动作。
- 训练目标是提升真实沟通能力，不引入操控、PUA、焦虑制造或强迫推进。

## 4. 模块架构

```text
app.js
├── optimizer.js          消息多版本优化与 Diff 数据
├── signals.js            社交信号多标签判断
├── timing.js             时机感规则和解释
├── replay.js             聊天记录解析与回放分析
├── micro-training.js     每日任务生成和掌握判定
├── growth.js             评分聚合和能力画像
├── textbook-search.js    长篇教材本地检索
├── learning-state.js     训练数据、版本迁移和持久化
├── prompts.js            MiMo Prompt 纯函数
├── coach.js              四维本地评分
└── long-content-index.js 长篇章节和复盘索引
```

现有模块 `coach.js`、`replies.js`、`prompts.js`、`stages.js`、`scenarios.js` 和 `long-content-index.js` 保持兼容。新增模块不得直接读取 DOM 或依赖 `app.js` 闭包。

### 4.1 统一分析结果

所有本地和模型分析统一使用以下结构：

```javascript
{
  source: "local | model | mixed",
  confidence: "high | medium | low",
  summary: "一句话结论",
  evidence: [
    { type: "message | pattern | timing", text: "对应证据" }
  ],
  risks: [],
  suggestions: [],
  scores: {
    naturalness: 0,
    empathy: 0,
    boundary: 0,
    momentum: 0,
    timing: 0
  }
}
```

### 4.2 持久化结构

在现有 `heartflow-state` 外增加版本号，旧数据读取时自动补默认值：

```javascript
{
  schemaVersion: 2,
  sessions: [],
  replayAnalyses: [],
  dailyTasks: [],
  growthSnapshots: [],
  signalAttempts: [],
  textbookProgress: {},
  settings: {}
}
```

新增消息可包含：

```javascript
{
  type: "me | her",
  text: "消息内容",
  createdAt: "2026-07-16T20:30:00+08:00",
  source: "user | model | local | seed"
}
```

旧消息缺少 `createdAt` 时使用 `null`，不推测历史发送时间，也不参与时机评分。

真实聊天回放默认只在内存中处理。用户主动保存时保存脱敏后的摘要、指标和分析结果，不默认保存原始文本。

## 5. 阶段一：即时沟通闭环

### 5.1 消息优化器 2.0

在现有发送前测验基础上增加三个版本：

- 原始版本：用户准备发送的原话。
- 低压力版：减少连续追问、评价和隐性压力。
- 主动推进版：保留边界，同时给出具体话题或轻量行动。

每个版本展示文本、Diff、修改内容、修改原因、适用阶段和潜在风险。

模型输出结构：

```javascript
{
  original: "...",
  lowPressure: {
    text: "...",
    changes: ["删除连续追问"],
    reason: "给对方更多选择空间"
  },
  proactive: {
    text: "...",
    changes: ["补充具体话题"],
    reason: "避免对话停在空泛表达"
  },
  recommendation: "lowPressure",
  confidence: "medium"
}
```

本地兜底至少生成低压力版，并过滤操控、贬低、诱导、强迫和越界表达。三个版本不能与原文完全重复，也不能改变用户的核心意图。

### 5.2 社交信号解读训练

用户先看女方消息，再从多项判断中选择，提交后查看答案、证据、误读风险和推荐方向。

基础标签：

- `positive`：积极或轻松
- `polite`：礼貌回应但投入不足
- `lowEnergy`：疲惫、忙碌或低能量
- `boundary`：表达边界或拒绝
- `closing`：准备结束本轮交流
- `ambiguous`：信息不足，不能确定

结果必须允许多标签：

```javascript
{
  labels: ["positive", "lowEnergy", "closing"],
  confidence: "medium",
  evidence: ["哈哈", "早点休息"],
  uncertainty: "无法仅凭这句话判断她是否愿意继续发展关系"
}
```

### 5.3 时机感评分

本地规则检查：

- 对方是否已经明确收尾。
- 用户是否在对方未回应时连续发送。
- 当前消息是否过长或包含多个问题。
- 当前阶段是否适合推进。
- 距上一条消息的间隔是否可用。
- 对方是否已经表达疲惫、忙碌或需要空间。

输出包含分数、标签、证据和动作建议。系统不得给出“必须等待几小时”的机械指令。

## 6. 阶段二：训练与成长闭环

### 6.1 对话回放分析

支持解析：

```text
我：最近工作怎么样？
她：还行吧，最近有点忙。
我：你是不是不高兴？
```

以及：

```text
**我：** 最近工作怎么样？
**夏紫桐：** 还行吧，最近有点忙。
```

分析内容：

1. 解析说话人和消息顺序。
2. 检查连续追问、过度解释和回应错位。
3. 分析双方主动发起、回复长度、反问和具体信息。
4. 判断冷却、边界、误读和修复机会。
5. 输出一个优先改进方向和替代表达。
6. 关联长篇教材中的相似复盘点。

原始聊天默认不上传、不长期保存，并提醒用户删除姓名、电话、学校、单位、地址和其他身份信息。

### 6.2 每日微训练

每天生成一个与当前短板相关的 5 分钟任务：

| 短板 | 任务示例 |
|---|---|
| 自然度 | 将过度解释压缩为两句话 |
| 共情 | 先回应对方感受，再表达自己 |
| 边界感 | 将施压表达改成可拒绝表达 |
| 推进力 | 补充一个具体且低压力的问题 |
| 信号判断 | 判断开放、礼貌、疲惫还是收尾 |
| 时机感 | 判断发送、等待或收尾 |

任务状态：

```javascript
{
  date: "2026-07-16",
  taskId: "empathy-respond-first",
  targetDimension: "empathy",
  prompt: "...",
  userAnswer: "...",
  score: 78,
  completed: true
}
```

同一天任务保持一致；连续 3 天完成后生成阶段复盘；连续 7 天后生成能力总结。不使用失败惩罚，只记录“已掌握、需要继续、尚未稳定”。

### 6.3 成长路径与能力画像

在现有趋势图上增加：

- 四维能力雷达图。
- 最近 7 天、30 天变化。
- 当前阶段掌握度。
- 高频错误类型。
- 本周训练建议。
- 本地、模型、介入练习和校准前数据来源标识。

某项能力只有同时满足以下条件才显示“初步掌握”：

1. 最近 5 次相关练习平均分达到 75。
2. 至少 3 次未触发同一风险信号。
3. 完成至少 1 次相关微训练。
4. 在至少 2 种场景中成功使用。

反馈使用行为描述，不给用户贴人格标签。

## 7. 阶段三：教材检索与引用

基于现有长篇索引增加本地轻量检索。检索字段包括：

- 章节标题和摘要。
- 小节标题。
- 复盘意图、好处、风险、修正。
- 原著男方回复和女方后续反应。
- 阶段、场景和风险标签。

返回最多 3 条结果：

```javascript
{
  chapterId: 3,
  reviewPointId: "3-r2",
  title: "低谷期的边界表达",
  matchedTerms: ["拒绝", "空间"],
  relevance: 0.86,
  excerpt: "...",
  reason: "与当前对话中的边界和邀约问题高度相关"
}
```

教练面板增加“教材依据”卡片，可跳转章节和复盘点。相关性不足时显示“暂无高相关教材依据”，不强行推荐。

MiMo 只接收当前对话摘要和最相关的 1–2 条复盘摘要，不接收整篇长文。模型负责解释教材如何帮助当前场景，不负责重新编造教材内容。

## 8. 统一数据流

```text
当前消息
  → 消息优化器 + 社交信号 + 时机评分
  → 训练结果
  → 短板识别
  → 每日微训练
  → 成长数据
  → 教材检索
  → 下一步练习
```

回放路径：

```text
脱敏聊天记录
  → 回放分析
  → 重复问题识别
  → 教材引用 + 每日任务
  → 成长画像更新
```

## 9. 错误处理

| 场景 | 处理方式 |
|---|---|
| MiMo 超时 | 显示本地结果并标注来源 |
| JSON 格式错误 | 兼容解析，失败后本地兜底 |
| 检索无结果 | 显示无高相关依据 |
| 旧状态缺字段 | 自动补默认值，不破坏旧会话 |
| localStorage 容量不足 | 停止保存原文，只保存摘要 |
| 缺少时间戳 | 不计算时机分，显示数据不足 |
| 用户取消发送 | 保留本地状态，不写入半条记录 |

## 10. 测试计划

在现有测试基础上新增：

- 消息优化器：版本完整性、意图保留、Diff、风险过滤、模型失败兜底。
- 社交信号：收尾、疲惫、边界、礼貌、不确定和多标签结果。
- 时机评分：缺少时间戳、连续发送、深夜、对方收尾和多问题。
- 回放解析：两种格式、异常行、说话人缺失、隐私脱敏。
- 每日微训练：日期稳定性、短板匹配、完成状态和连续天数。
- 成长画像：来源区分、掌握条件、空状态和旧数据迁移。
- 教材检索：关键词匹配、相关性排序、无结果和章节跳转数据。
- Prompt：字段快照、JSON 兼容解析和本地兜底。
- 端到端：输入消息 → 分析 → 任务 → 画像 → 教材引用。

目标：新增不少于 21 个测试用例，总测试数不少于 85 个，且保持零新增 npm 依赖。

## 11. 交付顺序

1. 统一数据结构、迁移和分析结果格式。
2. 完成消息优化器、社交信号和时机评分。
3. 完成回放分析、每日微训练和成长画像。
4. 生成教材检索索引并接入教练面板。
5. 完成 MiMo 失败路径、隐私提示和全量回归。

本设计只定义功能、架构、数据流和验收标准，不包含具体实现代码。实现前需要根据本设计继续生成独立的工程任务计划。
