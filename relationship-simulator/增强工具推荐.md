## HeartFlow 增强工具与技能推荐

基于测试结果和联网调研，以下是可直接集成到 HeartFlow 的工具、库和技能。

### 一、解决角色一致性问题（测试中发现的最大短板）

测试中 mimo-v2.5 在 4 个场景中有 3 个出现角色漂移。这不是模型能力问题，而是 prompt 结构问题。

**推荐方案：结构化角色锚定 Prompt**

当前 HeartFlow 的 system prompt 是一句话描述（"你扮演林知夏，23岁，慢热知性型"）。研究表明，结构化 prompt 可以显著提升角色一致性：

```
[角色身份] 林知夏，23岁，研一，慢热知性型
[行为规则]
- 回复不超过两句话
- 不主动表达好感，除非对方先释放明确信号
- 讨厌油腻、施压、过早暧昧
- 喜欢具体、有生活内容的对话
[禁止行为]
- 不说"宝贝""亲爱的"等亲密称呼
- 不主动邀约
- 不讨论感情状态
[当前阶段] 刚加微信后的第一晚
[对话历史摘要] 志愿活动认识，已加微信，聊了3轮
```

关键改进：把"她是什么样的人"改为"她应该怎么做 + 不应该怎么做"。行为指令比性格描述对模型的约束力强 3-5 倍。

**可参考的开源项目：**
- [AI角色扮演真实感研究](https://www.toutiao.com/zixun/7550090473948497920/) — 从"虚拟女友"到互动游戏的角色一致性方法论
- [State-of-the-Art Prompting for AI Agents](https://nlp.elvissaravia.com/p/state-of-the-art-prompting-for-ai) — 2026 年最新 prompt 工程综述

### 二、语音模式（P0 功能）

**最轻量方案：Web Speech API（零依赖）**

浏览器原生支持 TTS，不需要任何外部库或 API Key：

```javascript
function speak(text, { rate = 1.0, pitch = 1.1 } = {}) {
  const utterance = new SpeechSynthesisUtterance(text);
  utterance.lang = 'zh-CN';
  utterance.rate = rate;
  utterance.pitch = pitch;
  // 选择中文女声
  const voices = speechSynthesis.getVoices();
  const zhVoice = voices.find(v => v.lang.startsWith('zh') && v.name.includes('Female'));
  if (zhVoice) utterance.voice = zhVoice;
  speechSynthesis.speak(utterance);
}
```

集成难度：**低**。在 `app.js` 的消息渲染函数里加一个"播放"按钮即可。

**进阶方案：OpenAI TTS API**

如果需要更自然的语音（不同角色不同音色），可以接入 OpenAI TTS：

```javascript
// 在 server.js 加一个 /api/tts 路由
const ttsResponse = await fetch('https://api.openai.com/v1/audio/speech', {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${apiKey}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ model: 'tts-1', input: text, voice: 'nova' })
});
```

集成难度：**中**。需要新增 API 路由 + 前端 audio 播放。

参考：[Web Speech API 浏览器 TTS 实现](https://blog.csdn.net/bgfktz_942/article/details/162142381) | [speak.js 轻量方案](https://m.blog.csdn.net/gitblog_00118/article/details/154527846)

### 三、游戏化系统（P0 功能）

**推荐：自建轻量 XP 系统（不引入外部库）**

HeartFlow 是零依赖项目，不建议引入 npm 包。游戏化逻辑用 50 行 JS 就能实现：

```javascript
const GAMIFICATION = {
  xpPerRound: (score) => Math.round(score.total * 0.5),  // 评分越高XP越多
  levels: [
    { name: '恋爱新手', min: 0 },
    { name: '聊天学徒', min: 100 },
    { name: '氛围感选手', min: 300 },
    { name: '边界感大师', min: 600 },
    { name: '恋爱达人', min: 1000 },
  ],
  achievements: [
    { id: 'first_chat', name: '第一次开口', condition: (log) => log.length >= 1 },
    { id: 'streak_7', name: '连续7天', condition: (log) => countStreak(log) >= 7 },
    { id: 'boundary_90', name: '边界感满分', condition: (log) => log.some(l => l.score.boundary >= 90) },
    { id: 'all_personas', name: '三面镜子', condition: (log) => new Set(log.map(l => l.persona)).size >= 3 },
  ]
};
```

数据存在 localStorage 的 `heartflow-state` 里（已有 `trainingLog` 数组）。

参考：[Gamification Developer's Guide](https://dev.to/manishgiri1/gamification-that-actually-works-a-developers-guide-to-building-engaging-learning-systems-3841) | [Gamerzilla 开源成就系统](https://m.sohu.com/a/623045592_121124364/?pvid=000115_3w_a)

### 四、对话质量评估增强（P1 功能）

当前 coach.js 用正则匹配做评分，存在误报（如"没看出来"触发"出来"）。

**推荐：引入 NLP 评估维度**

学术界有成熟的对话评估框架可以借鉴：

| 维度 | 当前 HeartFlow | 可增强方向 |
|------|---------------|-----------|
| 自然度 | 长度 + 具体词检测 | 加入 perplexity 检测（用 LLM 判断"这句话像人说的吗"） |
| 共情 | 关键词匹配 | 加入情感对齐检测（她表达累→你是否回应了累） |
| 边界感 | 越界词列表 | 改为上下文感知（"出来"在"没看出来"里不算越界） |
| 推进力 | 问号计数 | 加入话题延续性检测（是否承接了上文话题） |

**具体修复：detectReplyFlags 误报问题**

```javascript
// 当前（有误报）：
const riskyWords = ["必须", "一定", "马上", "宝贝", "亲", "出来", "约吗"];

// 修复（加排除规则）：
const riskyPatterns = [
  { word: "出来", exclude: ["没看出来", "看不出来", "说出来", "表达出来", "表现出来"] },
  { word: "亲", exclude: ["亲切", "亲近", "亲自", "亲身"] },
  { word: "约吗", exclude: [] },
];
```

参考：[对话评估指标详解](https://m.blog.csdn.net/feng1790291543/article/details/162057266) | [CNIMA 通用评估框架](https://arxiv.org/html/2408.16518v1) | [Multi-Turn Interaction Survey](https://arxiv.org/html/2504.04717v3)

### 五、Prompt 版本管理（P1 功能）

HeartFlow 的 system prompt 散落在 `config.js` 和 `app.js` 里。随着角色和阶段增多，prompt 管理会变成噩梦。

**推荐：Prompt 模板文件化**

```
prompts/
├── personas/
│   ├── lin-zhixia.md      # 林知夏完整角色卡
│   ├── xu-yanqiu.md       # 许砚秋完整角色卡
│   └── tang-yihe.md       # 唐一禾完整角色卡
├── stages/
│   ├── 01-first-night.md  # 刚加微信
│   ├── 02-next-day.md     # 隔天轻联系
│   └── ...
└── templates/
    ├── coach-analysis.md  # 教练分析 prompt
    └── action-plan.md     # 行动计划 prompt
```

服务端启动时读取 markdown 文件，用简单模板引擎（`${persona.name}`）填充变量。

参考：[Prompt 版本化管理与 A/B 实验框架](https://blog.csdn.net/alex_goden/article/details/162652785) | [Top Open-Source Prompt Management Platforms 2026](https://agenta.ai/blog/top-open-source-prompt-management-platforms) | [PromptSource 模板协作工具](https://m.blog.csdn.net/gitblog_00845/article/details/156018465)
