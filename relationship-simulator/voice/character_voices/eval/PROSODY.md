# 说话方式（韵律）零成本改进对照（2026-11-08）

> ⚠️ **历史配置声明（2026-11-08 补记）**：本实验固定在旧参考 `R1_main8s` + `Japanese` 标签；当前生产已改为 `R5_sleep` + `Chinese`。「分段+400ms 留白有效、变速后处理禁用」作为**方法学结论**仍成立（S2 已于 2026-11-09 落地为前端分段请求 + 播放队列），但报告中的具体数值不可外推到新音色。

对应上一轮选项 A：标签路线收口后，转向**不改 `language`、不换参考音频、不改模型参数**的「说话方式」改进。核心问题：蝴蝶忍的轻柔、克制、留白能否靠文本/拼接/后处理补回来。

## 结论先行

1. **「分段合成 + 段间 400ms 静音」是唯一同时满足「改善说话方式 + 声纹零损伤」的手段**，但效应**只在中文本句显著**：最长停顿 `0.55s → 1.12s`（翻倍，噪声仅 0.06s）、停顿数 `1.2 → 2.0`、静音占比 `33.0% → 38.6%`，`speakerCos` 保持 `0.974`（与基线 0.975 无差）。日语中句的最长停顿 `0.72 → 0.93s` 落在噪声内，不显著。
2. **变速后处理明确有害，不推荐**。`stretch` / `seg_slow` 看起来「更克制」（`f0Std` 73.5 → 62.5 / 59.5、语速降到 5.5 / 5.1 字/s），但 `speakerCos` 稳定掉到 **0.952**（基线 0.975，Δ −0.023，噪声仅 0.003–0.005，4–12 倍）。这是 librosa phase vocoder 的伪影，不是真实韵律改善。**`f0Std` 下降不能单独当作「变克制」的证据，必须用 cos 守门。**
3. **文本停顿标记（`…`）不可靠，不推荐**。所有指标差异都在采样噪声内；中文 r2 出现 `44.15s` 生成耗时与 4.88s 的音频时长极差，说明省略号可能让模型生成超长/失控音频。它也是唯一让 `ttfa` 变差的手段（22.9 → 27.1s，+18%）。
4. **⚠️ `ttfa` 改善在当前链路下不会兑现**。`seg` 的「首段生成」是 `14.2s` vs 整句 `22.9s`（−38%），但 `character_server.synthesize()` 一次性返回完整 WAV，用户实际等待 `totalSynthSec`：中文 `24.9 → 30.1s`（**+21%**）。**只做服务端分段拼接会让中文变慢**。要兑现首响提前，必须改成前端按句分段多次请求 + 播放队列（边下边播）。这与上一轮「接口不支持真流式」的结论一致。

**本轮只做评测，未改动任何生产推理代码。**

## 实验设计

| 项 | 设置 |
|---|---|
| 固定不变 | `language=Japanese`（生产标签）、参考 `R1_main8s`、同一 prompt、`non_streaming=False`、同一模型/GPU |
| 唯一自变量 | 文本形态 / 分段与拼接 / 音频后处理 |
| 测试句 | `zh_m01` 稍微休息一下也没关系的，我会在这里陪着你。(21) / `ja_m01` 少し休んだらどうですか。お茶を淹れますよ。(21) |
| 重复 | `--repeat 2`，共 `2 句 × 5 变体 × 2 重复 = 20` 段有效音频；判定 `|Δ| > 1.5 × 组内极差` 才算 SIGNAL |
| 响度 | 全部统一 RMS 0.0900（实测 20 段 ratio 1.00x） |
| 隔离 | 产物写入 `out/prosody/`，与 P1 盲听基线、`out/langtag/` 物理隔离 |

| 变体 | 手段 | 额外推理 |
|---|---|---|
| `base` | 原文整句 | 生产基线 |
| `punct` | 句内标点 → `…` | 1 次 |

## 三种落地形态与权衡（尚未实施，等确认）

| 方案 | 改动范围 | 声纹 | 留白 | 用户首响 | 总耗时 |
|---|---|---|---|---|---|
| 现状 | — | 基准 | 0.64s | 22.9s | 22.9s |
| **S1 服务端中文分段拼接** | `character_server.py::synthesize` | 无损 | **1.03s** | 不变（等完整 WAV，中文反而 30.1s） | **+21%** |
| **S2 前端分段请求 + 播放队列** | 前端 `tts-client.js` / `app.js` | 无损 | **1.03s** | **14.2s（−38%）** | +13% |
| S3 变速后处理 | 服务端 | **−0.023** | 0.69s | 不变 | 不变 |

- **S2 是唯一同时改善 P0 与 P1 的路径**，且不改服务端推理；代价是前端要管理多次请求、播放队列与失败重试。
- S1 实现最简单，但**不建议单独上**：中文全句等待会从 24.9s 涨到 30.1s。
- 也可只对中文启用分段（日语 `seg` 不显著），做成按 `lang` 开关的策略。
- 无论哪个方案，都**不要**引入变速后处理。

## 已知问题与边界

- **执行层坑**：前台长命令连续两次被瞬时 `SIGTERM`；第一次残留的 Python 进程未死透，与后台任务争抢 6GB 显存（5731/6144 MiB），导致 10 分钟未跑完一次合成。清理后用**后台单进程**补跑成功（3m22s）。后续长评测一律用后台任务，并在启动前确认无同名残留进程。
- `n=2/组`，统计功效仍有限；`punct` 的异常值（44.15s）值得单独复现，但当前证据不足以推荐。
- 「轻柔、克制」的最终判断仍是**人耳听感**，客观指标只作守门与筛选。试听页里重点听 `zh_m01` 的 `base` vs `seg`（是否更自然）、`seg_slow`（有无金属声）、`punct`（省略号有没有被念出来）。
- 参考音频与生成音频均为第三方公开 AI 推理试听片段的衍生物，非动画原声、无开源授权声明。版权归 Aniplex / ufotable / 集英社，声优早见沙织。仅限本机个人非商业评测，禁止分发，对外展示须标注 AI 合成。
