# S2 前端分段播放队列（2026-11-09 实测）

对应上一轮 `PROSODY.md` 结论 4：「服务端分段拼接会让中文变慢，要兑现首响提前必须改成前端按句分段请求 + 播放队列」。本轮落地并做端到端实测。

## 结论先行

| 项 | 结果 |
|---|---|
| 首响 | **22.67s → 12.11s（−46.6%）** |
| 端到端播完 | 22.67s → 约 22.80s（**几乎持平，未变慢**） |
| 使用音色 | **最新蝴蝶忍**：`refs/shinobu_sleep_ref.wav` / `language=Chinese` / `xVectorOnly=true` / `refText=""` |
| 是否真流式 | **否**。Qwen3-TTS 一次性返回完整 WAV；S2 是工程分段（多次请求 + 播放队列） |

设计目标「首响提前、总时长不劣化」已达成。测试句「稍微休息一下也没关系的，我会在这里陪着你。」（21 字），三段链路 `:3000 → :5001 → :5002` 全部真实请求。

## 异常与边界（如实记录）

1. **预热 69.88s 不是模型加载慢**。`character_server` 日志显示模型仅 `8.1s` 就绪；真正原因是 `:5001` 的 `boot()` 自动热用了默认音色 `char_klee`（`x_vector_only=False`，12 字）跑了一次 **74.0s** 的完整克隆合成，占住 GPU 推理锁，蝴蝶忍的预热请求排队到其后（自身仅 3.2s）。**首次启动会明显偏慢，之后稳定**；本次 A/B 数据均在热身结束后采集，不受影响。
2. `qwen_tts` 启动时提示 `SoX could not be found` 与 `flash-attn is not installed`，仅为警告，未影响合成。
3. GPU 占用 `5791 / 6144 MiB`，接近满载；6GB 显存下无法再并行加载其它模型。
4. 命令行无播放器，B 的「端到端估计」按各段请求串行累计 + 400ms 留白计算，是**上界**；浏览器里后续段在首段播放期间并行预取，但 GPU 单进程推理锁会排队，实际落在该区间内。真实听感请以试听页为准。
5. **旧评测结论不可外推**：`BASELINE.md` / `LANGTAG.md` / `PROSODY.md` 全部基于旧参考 `R1_main8s`（8s/24kHz）+ `Japanese`。尤其「维持 `Japanese` 标签」在新参考上**未复验**，而生产已由用户改为 `Chinese`，不要据此回退生产配置。新配置评测命令见 `README.md` 配置漂移节。
