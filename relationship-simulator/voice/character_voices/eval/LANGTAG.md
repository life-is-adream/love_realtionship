# 语言标签 2×2 对照实验（2026-11-07 / 11-08）

> ⚠️ **历史配置声明（2026-11-08 补记）**：本实验固定在旧参考 `R1_main8s` + 旧生产标签 `Japanese` 上做对照。当前生产已由用户主动改为 `R5_sleep` + `language=Chinese`。因此下文「维持 `Japanese`」的结论**不适用于当前生产配置**，也不构成回退生产的理由；如要在新参考上复验，见 `README.md` 配置漂移节的命令。

对应上一轮「选项 C」的验证请求：**生产配置 `char_shinobu.language = "Japanese"`，中文句子也是用日语标签念的，改成中文标签能否零成本改善中文发音？**

## 结论先行

1. **不建议改生产配置，维持 `Japanese` 标签。** 改成 `Chinese` 标签后，中文中句的说话人相似度下降 `0.013`（约为重复间噪声的 6 倍）、基频下降 `63Hz`、语速加快 `1.27 字/s（+21%）`。方向与蝴蝶忍「轻柔、克制、留白」的目标相反。
2. **「改中文标签改善中文发音」这一假设未被数据支持。** 客观指标显示的是整体声学画像被改变（更低、更快、更亮、留白更少），而不是发音更清晰。发音清晰度本身无法由客观指标判定，须靠试听页人耳判断。
3. **唯一实质收益在 P0 延迟**：中文标签让中文中句生成从 `28.98s → 22.77s`（**−21.4%**），日语中句 `23.92s → 20.77s`（−13.2%）。这是一个明确的「拿相似度换延迟」的权衡，不是免费改进。
4. **日语句换标签几乎无影响**（`speakerCos` Δ=−0.002 ≈ 噪声），反向印证日语标签对日语句是正确配置。
5. **方法学修正**：短句（4–6 字）单次采样噪声极大（同一组重复间 `f0` 极差最高 `135Hz`、语速 `±1.77 字/s`），**不能用短句指标做决策**；判别力来自中句（21 字，`f0` 极差 5–45Hz）。

**本轮未改动任何生产推理代码。** `character_server.py` / `tts_server.py` 保持原样。

## 实验设计

| 项 | 设置 |
|---|---|
| 控制变量 | 参考音频固定 `R1_main8s`（当前生产参考）；同一 `voice_clone_prompt`、`x_vector_only_mode=True`；`non_streaming_mode=False`；同一模型/同一 GPU/同一进程 |
| 唯一自变量 | `generate_voice_clone(language=...)` → `Japanese`(j) vs `Chinese`(c) |
| 测试句 | `ja_s01` こんにちは。(6) / `zh_s01` 你好呀。(4) / `ja_m01` 少し休んだらどうですか。お茶を淹れますよ。(21) / `zh_m01` 稍微休息一下也没关系的，我会在这里陪着你。(21) |
| 重复 | 每组 `repeat=2`，用于估计采样噪声；共 `4 句 × 2 标签 × 2 重复 = 16` 次真实合成 |
| 判定规则 | `|Δ| > 1.5 × 重复间极差` 记为 `SIGNAL`，否则视为噪声 |
| 隔离 | 全部写入 `out/langtag/`，与 P1 盲听基线 `out/wav/` 物理隔离。直接跑 `run --lang-tag Chinese` 会因 WAV 文件名不含标签而**覆盖盲听基线**，故新增独立 `langtag` 子命令 |
| 响度 | 所有 WAV 统一 RMS `0.0900`（实测 16 段 ratio `1.00x`），消除音量偏差 |

## 解读与边界

- **`speakerCos` 只作相对排序**：上一轮已发现模型自带 speaker encoder 对不同参考片段区分度不足（0.945–0.981）。此处 Δ 虽稳定超噪声，也不能直接等同于「人耳更像蝴蝶忍」，只说明输出相对参考声纹发生了系统性偏移。
- **发音清晰度是本轮唯一未自动化的维度**：中文咬字、日语假名是否自然，客观指标看不出来。请听 `http://127.0.0.1:3000/voice-langtag/index.html`，重点听 `zh_m01` 的两组 4 段。若中文标签明显更清楚，那属于「清晰度」与「角色还原度」的取舍，需你判断权重。
- **统计功效有限**：`n=2/组`。若要定论，跑 `--repeat 5` 并加入长句（`zh_l01` / `ja_l01`），预计 10–15 分钟。
- **延迟收益的来源**：中文标签下音频更短（21 字句少约 1.1s），自回归生成 token 更少，故更快。这属于「说得快」而非「算得快」，与 P0 的 3 秒目标无关。

## 复现

```bat
cd relationship-simulator
set PY=E:\heartflow-voice\venv-qwen\Scripts\python.exe
set EV=voice\character_voices\eval\evaluate.py

:: 短句组（本轮第一批）
%PY% %EV% langtag --cases ja_s01,zh_s01 --tags j,c --refs R1_main8s --repeat 2

:: 中句组（判别力更强，结果累积进同一 results.json / index.html）
%PY% %EV% langtag --cases zh_m01,ja_m01 --tags j,c --refs R1_main8s --repeat 2

:: 提高统计功效
%PY% %EV% langtag --cases zh_l01,ja_l01 --tags j,c --refs R1_main8s --repeat 5
```

产物：`out/langtag/{results.json, index.html, wav/*.wav}`；网页副本 `public/voice-langtag/`（已加入根 `.gitignore`）。`langtag` 默认 skip-existing，可用 `--force` 全部重算。
