从恋爱输入法到恋爱训练器
Lovekey 能给 HeartFlow 什么

把 Lovekey键盘（恋爱聊天输入法）的产品/设计拆解，翻译成你这个 HeartFlow 恋爱模拟器 可直接落地的设计借鉴与技术路线。重点新增一节：联网搜索 / RAG 检索增强如何补强你已有的本地教材检索。

一句话结论：Lovekey 用「悬浮球 + 亲密度可视化 + 人设即 Prompt」验证了 Z 世代恋爱社交刚需确实能跑通商业化（年营收 ¥3100 万、月活 200 万+）；但它踩的三个坑——油腻不真诚、隐私信任、续费摩擦——恰好是你 HeartFlow「本地优先、训练真实沟通能力」路线可以直接反击的差异化卖点。把它的好交互借来，把它的坏账做成你的信任设计，再用 RAG / 联网搜索把现有的本地关键词检索升级成语义检索。

01

两条路线，一个赛道

Positioning contrast
🟠 Lovekey：帮你「说」
  • 产品本质：输入法插件，复制对话 → AI 生成 3–5 条回复 → 粘回。替用户把话说了。
  • 价值主张：降低恋爱社交焦虑，让回复「高情商、不冷场」。
  • 商业模式：高客单订阅（¥48/月）+ 终身锚定（约 ¥128），付费墙是核心转化手段。
  • 核心风险：把恋爱变成可量化数据游戏，话术油腻、隐私存疑、续费投诉多。
🟢 HeartFlow：教你「会」
  • 产品本质：本地运行的对话训练器，仿微信界面 + 教练层，练的是真实沟通能力。
  • 价值主张：感觉提供动力，理性负责方向/边界/长期经营——不教 PUA 套路。
  • 商业模式：本地免费、零依赖、隐私优先，无订阅墙；需要模型时走用户自有 Key。
  • 核心优势：已内置 A/B/C 回复建议、四维评分、发送前风险测验、7 阶段训练、本地教材检索。

03

设计启示：该借的借，该改的改

Design takeaways
✅ 可直接借鉴
  • 悬浮球三步流：聊天内零切换呼出教练，降低使用摩擦。
  • 亲密度/关系进度可视化：把抽象「关系进展」做成可滑动、带解锁进度的控件。
  • 人设即 Prompt 的市场化封装：角色卡 = 可分享、可组合的人设配置。
  • 情绪化配色体系：用色温传达教练反馈的情绪强度。
⚠️ 必须改进 / 反向设计
  • 加「真诚度 / 语气强度」独立滑块，对抗油腻——让用户主动调弱套路感，呼应你「真实沟通」理念。
  • 可验证的信任设计：数据流向提示、本地处理状态徽标，补 Lovekey 最弱的隐私一环。
  • 付费墙更克制透明：你本就本地免费，把这点做成首屏信任声明。
  • 差异化记忆点：Lovekey 与蜜小语视觉雷同；你用「训练器」定位 + 浪漫暖色 + 理性结构做出区隔。
04

联网搜索 / RAG 检索增强：怎么落到你项目

Web search & RAG for HeartFlow
现状盘点

你已经有的：本地关键词检索

HeartFlow 当前用 textbook-search.js + 构建索引 long-content-index.js 做本地关键词检索（BM25 类），只发脱敏摘要、不上传整篇教材。这是很好的隐私基底，但只能「字面匹配」，做不到「语义理解」——比如用户问「她半天没回我要不要主动」，检索不到教材里「冷却期 / 投入度」相关段落。

① 缓存层
高频教材片段 / 心理学依据缓存，命中即返，降成本降延迟
→
② 检索层（混合）
BM25 关键词 + 向量语义；教材库 + 可选联网白名单源并行
→
③ 验证 / 重排
重排序精筛 + 置信度评估 + 引用溯源；不足则触发拒答/联网
→
④ 生成层
把检索片段作为上下文喂给教练层 / 角色，带「依据来源」输出
建议路线：先把 ①+②+③ 做成本地版（FAISS/Qdrant 本地向量库 + BGE 等中文 embedding），④ 沿用现有模型代理。联网搜索（白名单 .gov/.edu/权威机构）作为可选增强，默认关闭。
本地优先（P0）

语义检索升级（RAG 内核）

把 17.4 万字教材 + 10 章课程做动态分块 → embedding → 本地向量库。混合检索（BM25 + 向量）替代纯关键词，让教练引用更准。沿用你「只发脱敏摘要」的边界，向量索引留在本地，不外发。

谨慎可选（P1）

联网搜索增强（Web Search）

用 web_search_options 或模型后缀 :surfing 接入实时检索，仅限白名单权威源（心理学机构 / 学术站 / 官方指南），给教练层提供「最新沟通研究」背书。注意：联网=上下文可能外发，与你隐私优先冲突，必须默认关、需用户显式开启、只检索公开通用知识、不发送对话原文。

架构（P1）

Agentic RAG：让教练自己决定查不查

把检索作为教练层（Coach Layer）可自主调用的工具：当某句回复需要教材依据或心理学支撑时，由教练判断触发检索、评估信息是否充分后再生成——多步、可控、可追溯。

成本 / 风险护栏

缓存 · 限流 · 延迟 · 幻觉

高频教材片段缓存 + QPS 限流控成本；向量检索 + LLM 用异步 / 渐进式响应（先给摘要再补依据）控延迟；RAG 减少但不消除幻觉，需置信度评估 + 引用溯源，不足时明确「依据不足」。

05

把 Lovekey 的短板，做成你的信任设计

Privacy as differentiator

🔒 HeartFlow 已有的隐私基底（直接用作卖点）

  • 本地优先：核心训练（分析 / 评分 / 教材检索）不需要 API Key 也能跑，模型生成才走用户自有 Key。
  • 脱敏外发：真实聊天回放只在浏览器内存处理；发往模型前必须点按钮，且仅发脱敏摘要 + 最多两条短摘录，原始回放不写入学习状态。
  • 可验证：「联网搜索」若上线，默认关闭 + 白名单 + 审计日志，让数据流向对用户可见、可关。

对比 Lovekey「宣传本地生成、实际联网 AI 输入法、隐私协议说法不一」——你这套正好补上它最弱的一环，建议在首屏用一条信任声明把它讲明白。

落地优先级清单

Implementation priority
P0

本地语义检索升级（RAG 内核）

把关键词检索升级为 BM25 + 向量混合检索，教材/课程本地 embedding、本地向量库。直接提升教练引用准确率，且不触碰隐私边界。

P0

关系进度可视化

把现有 7 训练阶段做成可感知的关系进度条 + 解锁动画，借鉴 Lovekey 的情感化范式，强化「成长感」。

P1

教练悬浮快速呼出

聊天内长按消息即呼出 A/B/C 与四维评分，减少面板切换，借 Lovekey 悬浮球三步流但贴你的训练场景。

P1

「真诚度 / 语气强度」独立滑块

让用户主动调弱套路感，正面回应 Lovekey「油腻」争议，强化你「真实沟通」的差异化定位。

P1

联网搜索（谨慎可选）

白名单权威源 + 默认关闭 + 审计日志，仅给教练层提供实时心理学依据背书；明确不发送对话原文。

P2

角色市场 / 角色卡分享

把人设即 Prompt 封装成可分享角色卡，社区化分发，做 Lovekey「人设市场」的开放版。
