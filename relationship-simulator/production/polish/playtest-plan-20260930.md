# HeartFlow Playtest 计划草案（2026-09-30）

> 执行人：严守真（quality-lead）· Task T1-POLISH-QA-20260930
> 项目：HeartFlow 恋爱模拟器——想练恋爱沟通的年轻人的本地练习场（对话模拟 + 四维信号评分 + 教练反馈 + 微训练 + 长篇对照复盘）
> 性质：草案，供主理人与文策/工程确认后定稿。本轮未接触任何真实测试者。

---

## 一、总体设计

| 轮次 | 定位 | 人数 | 形式 | 前置条件 |
|------|------|------|------|----------|
| R1 | 内部烟雾 + 核心闭环验证 | 2-3 人（项目成员/熟悉者） | 本地跑全流程 + 缺陷记录 | 测试基线 371/371 绿；B1/B2 小修合入 |
| R2 | 目标用户首轮：新玩家体验 + 核心价值验证 | 5-8 人 | 一对一远程/线下陪同测试（think-aloud） | R1 阻断/Major 清零 |
| R3 | 深度验证：中盘系统 + 难度曲线 + 反 PUA 边界感知 | 8-12 人（含 2-3 名高敏感/有不良经历子集，自愿） | 独立自测 + 事后访谈 | R2 卡点修复；问卷定稿 |

**总周期建议**：4-5 周（R1 第 1 周，R2 第 2-3 周，R3 第 4-5 周）。

**用户画像（目标用户 = 想练恋爱沟通的年轻人）**：
- P1「零经验谨慎型」：18-24 岁，无/少恋爱经历，社交焦虑，怕说错话；痛点=不知道开口后怎么接。
- P2「有经历但受挫型」：22-28 岁，聊过没结果，容易用力过猛或讨好；痛点=节奏感与边界感。
- P3「成长型」：20-30 岁，有稳定关系但想提升沟通质量；痛点=把练习迁移到真实关系。
- R3 附加子集 P4：有过被 PUA/高压追求经历的用户——只邀请自愿者，全程可退出，界面已具备识别/防御训练模式（anti/pua 双模式），测试前单独知情说明。

## 二、每轮任务脚本

### R1 内部烟雾（每测试者 ~40 分钟）
1. 冷启动：`node server/index.js` → 打开首页，确认无白屏、无 console 错误、字体加载失败时页面仍可用。
2. 对话闭环：选默认角色 → 连续 10 轮对话 → 发送含"晚安"的消息验证收尾识别 → 切换 anti/pua 模式各发 3 条，确认边界提示出现。
3. 评分与教练：发送前测验 → Diff 高亮正常渲染（无 `<ins>` 字面量）→ 教练浮窗展开 → 浮窗联网搜索证据卡片显示。
4. 微训练 + 成长：完成 1 次改写训练（含中文引号引用原话的场景）→ 查看成长档案时间线无重复 legacy 事件。
5. 长篇对照：打开长篇第 3 章对照复盘 → 断网刷新页面，确认 localStorage 状态恢复。
6. 异常路径：停掉 server 后点发送 → 确认本地回退文案而非崩溃。
- **产出**：缺陷清单（按 Blocker/Critical/Major/Minor 分级）+ 烟雾 PASS/FAIL 门控。

### R2 新玩家首轮（每测试者 ~50 分钟，陪测者只观察不指导）
| # | 任务 | 观测点 |
|---|------|--------|
| T1 | "刚加了一个有好感的人的微信，不知道怎么开场——你来试试"（无引导自由探索 ≤5 分钟） | 首次有效发送耗时；是否找到输入框/角色选择；卡点记录 |
| T2 | "看看系统怎么评价你刚才那条消息" | 是否自行发现发送前测验/信号面板；四维评分是否被理解 |
| T3 | "按教练建议改写一条再发" | Diff 视图是否理解；采用/放弃改写的比例 |
| T4 | "换个练习目标：她今天说'最近加班好累'"（压力/边界场景） | 是否识别疲劳信号；是否出现施压话术；系统提示是否起效 |
| T5 | "完成一次微训练" | 训练完成率；改写评分反馈是否被读懂 |
| T6 | "看看你到第几阶段了，下一步该干嘛" | 成长档案/阶段进度可发现性 |
- **结束后**：出声访谈 10 分钟（SUS 5 题快测 + 开放问题）+ 填 R2 问卷。

### R3 中盘与难度曲线（自测 3 次 × 20 分钟跨 3 天 + 访谈 30 分钟）
1. 连续 3 天会话：覆盖 7 阶段推进（刚加微信→隔天联系→邀约→约会后→暧昧→表达好感→确定关系），记录每阶段停留轮数与四维评分趋势。
2. 难度卡点：标记"连续 3 轮评分无提升"的阶段——判断是用户问题还是系统反馈不足。
3. 反 PUA 边界：在 pua 模式下故意输入查户口式连问、"为什么不回我"施压、过快表白各 2 条，验证介入提示的时机、语气、可跳过性；用户是否感知到"被说教"（反向指标：提示出现即被关掉的比例）。
4. 长篇对照迁移：用长篇剧本对照复盘 1 次，评估"参考他人对话→改进自己"的迁移感。
5. P4 子集（自愿）：额外完成边界舒适度自评（1-10），任何 ≤4 者立即停止该子测试。

## 三、观测指标

**核心四维评分趋势**（每轮会话自动记录，导出 CSV 分析）：
1. 四维评分（好奇/共情/边界/节奏——以实际实现维度为准）逐会话均值与斜率：R3 目标 = 3 次会话内至少 2 维呈上升趋势。
2. 首条消息质量分 vs 第 N 条质量分差值（学习曲线是否存在）。

**任务完成率**（R2 六任务）：
- T1 首发成功率 ≥80%、T2 评分发现率 ≥70%、T5 训练完成率 ≥70% 为达标线；低于线即记 P1 体验卡点。

**卡点指标**：
- 每任务"卡住 >60 秒 / 请求帮助 / 放弃"计数，定位 top3 卡点界面。
- 阶段停滞率：R3 中停留在同一阶段 >8 轮的会话占比（目标 <20%）。

**反 PUA 边界有效性**：
- 施压话术触发介入提示的召回率（应 100%）；误伤率（正常关心被提示 <10%）；提示后用户话术修正率（≥50% 为有效）。

**技术健康度**（陪测者记录）：白屏/报错/接口失败次数 = 0；页面加载（含 1.08MB 索引）可感知卡顿记录（为 B7 拆包提供数据）。

## 四、问卷题目

### R2 快测（10 题，5 分钟）
1. 整体满意度 1-5 分。
2. "这个工具最让你想继续用的一点是什么？"（开放）
3. "哪一步你不知道该干什么？"（开放，对应卡点）
4. 四维评分"看懂了吗"：完全没懂/大概/清楚（单选）。
5. 教练建议"像人话吗"：像说教/中性/像朋友（单选）——**检测说教感，反 PUA 产品基调的关键反向指标**。
6. 改写建议你实际采用了吗：采用了/看了没采用/没看（单选）。
7. "练习的角色对话像真人吗" 1-5 分。
8. "你会推荐给朋友吗" 0-10（NPS）。
9. 隐私舒适度："知道对话只存在你本地、脱敏后才可能用于分析，你的感受？" 舒适/一般/不安。
10. "如果只能改进一处，改什么？"（开放）

### R3 深访提纲（30 分钟，半结构化）
- 三天练习里，哪一刻你觉得"自己真的进步了"？哪一刻想放弃？
- 系统的边界提醒：有过不舒服吗？提示的措辞和时机怎么改更好？
- 四个评分维度，你觉得哪个最准/最不准？
- 学到的话术，你敢在真实聊天里用吗？举一个例子（迁移性检验）。
- P4 附加：练习过程中有没有内容让你想起不好的经历？（如有 → 立即提供暂停/退出，不追问细节）

## 五、隐私与合规自查清单

**项目内建边界（测试前自查确认仍然生效）**：
- [ ] 反 PUA 契约在 prompt 层仍生效；剧本/教练内容守边界优先。
- [ ] 信号分类保守（礼貌≠兴趣），评分不会鼓励施压话术。
- [ ] 对话数据默认 localStorage 本地存储；replay 本地分析；`redactSensitiveText` 脱敏（邮箱/网址/电话/长数字）在联网分析路径前执行。
- [ ] Relationship Intelligence 的 consent 开关关闭时不持久化增强记忆（serializeStateForStorage 已含 `_enhanced` 清理逻辑）。

**测试执行合规**：
- [ ] 所有测试者签署知情同意书：说明数据如何记录（屏幕录制/问卷/访谈笔记）、存储位置、保留期限（建议 ≤90 天）、退出与删除权利。
- [ ] P4 高敏感子集单独二次知情确认；测试中可随时无理由退出且不影响任何回报；不采集真实恋爱对象信息。
- [ ] 测试数据与个人身份分离存储（编号制）；访谈录音需单独口头确认。
- [ ] 未成年人（<18）不纳入测试范围。
- [ ] 若使用联网 LLM 分析测试会话：确认"原始对话不进模型"承诺对测试数据同样成立；如不成立须在同意书中明示。

**拟人化互动服务自查（对照 2026-07-15 施行的《人工智能拟人化互动服务管理暂行办法》）**：
- [ ] **用户知情**：首屏显著位置明示"对方为 AI 模拟角色，非真人"（建议加一次性首访提示条；测试前检查当前 index.html 是否已有该标识，若无需列为 P1 需求交 engineering-lead）。
- [ ] **防沉迷与真实关系提示**：产品不得以拟人化情感陪伴替代真实社交——在成长档案/阶段进度页保留"练习用于现实沟通"的引导文案；R3 访谈验证用户未产生"把 AI 当真实对象"的混淆。
- [ ] **情感操纵防护**：AI 角色不得使用情感操控话术挽留用户（pua 模式仅用于"识别训练"，必须保持"只用于防御"的定位与确认弹窗）。
- [ ] **未成年人保护**：无未成年模式设计前不面向未成年人开放。
- [ ] **投诉与退出机制**：提供会话一键清空（resetSession 已有 ✓）与数据导出（exportSession 已有 ✓）。
- [ ] 上线前建议由主理人组织一次法规条文逐条比对复核（本清单按任务给定名称整理，正式合规评审需以法规原文为准）。

## 六、门控与签收

- R1 → R2：烟雾 PASS（Blocker/Critical = 0）方可放行。
- R2 → R3：top3 卡点修复 + 任务完成率达标注线，或主理人明确豁免。
- 每轮产出：`production/playtests/round-N-report.md`（缺陷分级清单 + 指标数据 + 结论）。
- 最终签收：三轮指标达标 + 合规自查全勾 + 用户（主理人）签字确认——质量门为建议性，放行权在用户。
