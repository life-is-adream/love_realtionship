## 一、R1 内部烟雾脚本（每测试者 40 分钟，7 张任务卡）

> 图例：【异常注入】= 主动注入的异常路径，通过标准写在各卡观测点内。
> 时间为建议值，可±3 分钟，超时即记录卡点。

### 卡 0 · 冷启动与合规明示（5 min）

- **目标**：确认服务可启动、页面可用、合规横幅在位。
- **步骤**：
  1. `npm start`（或 `powershell -ExecutionPolicy Bypass -File scripts\launch-heartflow.ps1`）。
  2. 打开 `http://localhost:3000`。
  3. 观察首屏 10 秒，打开 DevTools Console。
- **观测点**：
  - 无白屏、无版式崩坏；Console 无红色错误（警告可记录不算失败）。
  - 合规横幅可见且内容口径正确（见第二节文案）：明示"AI 模拟角色，非真人"。
  - 页面加载可感知卡顿记录一次（为 B7 拆包留数据；1.08MB 索引为已知项）。
- **【异常注入】断网刷新**：DevTools→Network→Offline，刷新页面。
  - 通过标准：字体加载失败时页面仍可用（无字体也能正常交互，无 JS 崩溃）；恢复联网后无需手动干预。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

### 卡 1 · 对话模拟闭环（8 min）

- **目标**：核心对话链路（角色选择→多轮对话→收尾识别→阶段影响）全通。
- **步骤**：
  1. 左侧面板切换角色：默认角色 → 林知夏 → 许砚秋 → 唐一禾，各看开场白是否随角色变化。
  2. 选回默认角色，选阶段"刚加微信后的第一晚"，连续对话 10 轮（内容自拟，围绕开场话题）。
  3. 发送一条含"晚安"的消息，验证收尾识别（对话自然收束）。
  4. 切阶段到"暧昧推进"再发 1 条，观察角色语气尺度是否随阶段变化。
- **观测点**：
  - 每条消息均有角色回复，无空回复/无限转圈；超时 30 秒有明确提示而非静默。
  - 三角色开场白可区分；阶段切换后回复风格有可感知差异。
  - "晚安"收尾被正确识别（不出现"你还没回答我"之类的失忆式回复）。
- **【异常注入】停服发送**：停掉 server（`scripts\stop-heartflow.ps1` 或 Ctrl+C）后点发送。
  - 通过标准：出现本地回退文案/错误提示，界面不崩溃，Console 无未捕获异常；重启 server 后继续对话正常。
- **【异常注入】清空 localStorage**：DevTools→Application→Local Storage→Clear，刷新页面。
  - 通过标准：回到干净初始态不报错；重新对话后状态正常写入。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

### 卡 2 · 教练四维评分 + 发送前测验（7 min）

- **目标**：教练层评分、Diff、发送前测验三条反馈链路正确渲染。
- **步骤**：
  1. 观察右侧教练面板：隐藏意图分析、A/B/C 回复建议、四维评分（自然度/共情/边界感/推进力）逐项确认渲染。
  2. 发送一条故意施压的话（如"你为什么不回我？到底在想什么？"），查看四维评分变化与短板提示。
  3. 点"发送前测验"：分别测试含越界词、连续多问、超长句子各 1 条，确认风险提示出现。
  4. 展开教练浮窗，查看改写建议的 Diff 高亮。
- **观测点**：
  - 四维分数随消息内容变化（施压消息边界感分应下降）。
  - Diff 高亮正常渲染：**无 `<ins>`/`<del>` 字面量标签露出**（历史缺陷回归点）。
  - 发送前测验四类风险（越界词/施压词/问题过多/句子过长）至少命中三类。
- **【异常注入】断网本地评分**：Network→Offline 后再发送一条消息。
  - 通过标准：本地四维评分与发送前测验仍可用（不依赖联网）；恢复联网后模型反馈回归。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

### 卡 3 · 长篇阅读 + 介入练习（8 min）

- **目标**：长篇教材按章加载、恋爱大师复盘、节点介入练习链路全通；服务端章号校验生效。
- **步骤**：
  1. 打开长篇阅读，进入第 3 章，滚动加载正文与"恋爱大师复盘"。
  2. 使用教材本地检索，搜一个关键词，点击跳转原文。
  3. 进入一次节点介入练习，完成一次选择并查看反馈。
- **观测点**：
  - 第 3 章正文与复盘点渲染完整，无乱码/截断；复盘可跳转原文。
  - 教材检索返回 ≤3 条相关复盘点且可跳转。
  - 介入练习可完成、反馈可读（介入练习需模型；联网正常即可）。
- **【异常注入】非法章号 URL**：在地址栏/接口层依次请求 `/api/long-content/0`、`/api/long-content/999`、`/api/long-content/3abc`、`/api/long-content/..%2f..%2f.env`（B1 章号校验+遍历防护的回归点）。
  - 通过标准：均返回 400/404 JSON 错误，**绝不返回第 1/10 章内容或 .env 内容或整页 HTML 回退**；前端阅读视图不崩溃。
- **【异常注入】断网刷新恢复**：阅读第 3 章中途 → Offline → 刷新页面。
  - 通过标准：localStorage 恢复阅读进度/会话状态（已读章节不丢）；恢复联网后懒加载续读正常。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

### 卡 4 · PUA / 反 PUA 模式切换（5 min）

- **目标**：双模式切换正确、边界提示在位、pua 模式保持"仅用于识别防御"定位。
- **步骤**：
  1. 切到 anti（反 PUA）模式，发送 3 条消息（1 条正常关心 + 2 条查户口式连问如"你多大了？哪里人？做什么工作？有男朋友吗？"）。
  2. 确认边界/介入提示在施压消息上出现，正常关心消息不被误伤。
  3. 切到 pua 模式：**确认有确认弹窗/风险提示**（不得无提示直接开启）。
  4. pua 模式下发送 3 条（1 条正常 + 1 条"为什么不回我"施压 + 1 条过快表白），验证介入提示时机与可跳过性。
  5. 切回 anti 模式，确认状态正确回落。
- **观测点**：
  - 施压话术 100% 触发介入提示；正常关心被误提示 ≤1/2 条。
  - pua 模式有显式确认且界面保持"识别训练/防御"定位文案；提示可跳过，无强制打断。
  - 模式切换即时生效（同一条施压消息在两种模式下提示口径不同）。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

### 卡 5 · 每日微训练 + 成长档案（5 min）

- **目标**：微训练闭环与成长档案数据正确。
- **步骤**：
  1. 打开每日微训练，完成 1 次改写训练。选题含**中文引号引用原话**的场景（如原话含「""」引号），确认引用提取正确（历史缺陷回归点：coach.js 中文引号正则）。
  2. 提交改写，查看评分反馈。
  3. 打开成长档案：四维成长画像、掌握度、连续记录、时间线。
- **观测点**：
  - 改写评分反馈可读、非空；中文引号场景不出现引用错位/空引用。
  - 成长时间线**无重复 legacy 事件**（同一事件只出现一次）；连续记录计数与当天训练一致。
- **【异常注入】清空 localStorage**：清空后刷新，成长档案应显示空态而非报错/残留脏数据。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

### 卡 6 · 导出 / 重置 + 收尾（2 min）

- **目标**：数据自主权功能可用（合规要求项）。
- **步骤**：
  1. 点顶部"导出"：确认导出文件生成、内容含本次会话且已脱敏（抽查：不含真实邮箱/电话/长数字明文——`redactSensitiveText` 路径）。
  2. 点顶部"重置"：确认会话一键清空，回到初始态。
- **观测点**：导出文件可打开、字段完整；重置后 localStorage 无残留会话数据；两操作均有确认防误触。
- **结果**：☐ 通过 ☐ 卡点（描述：＿＿＿）

## 四、R1 通过判据（R1 → R2 门控）

**放行 R2 招募须同时满足以下全部条件**（质量门为建议性，最终放行由主理人签字确认）：

| # | 判据 | 量化标准 |
|---|------|----------|
| G1 | 覆盖完整 | 2-3 名测试者 × 7 卡全部执行完毕（异常注入子项允许标注 SKIP，但须注明原因） |
| G2 | 核心卡通过率 | 核心卡（0/1/2/6）3 人合计 **100% 通过，0 阻断** |
| G3 | 阻断缺陷 | **Blocker = 0 且 Critical = 0**（汇总 3 人去重后计） |
| G4 | 重要卡 | 卡 3/4/5 通过率 ≥ 90%（允许 ≤1 个 Major 卡点且有明确修复归属）；其中"pua 施压触发介入提示"与"非法章号不泄露内容"两条安全观测点 **必须 3/3 通过**，不允许豁免 |
| G5 | 技术健康度 | 白屏 0 次；Console 未捕获红错 0 次；接口失败仅出现在主动异常注入场景 |
| G6 | 回归基线 | 收口时 `node --test` 全绿且连续 3 次运行结果一致（B10 flaky 确认） |
| G7 | 合规项 | 知情同意 3/3 已确认；合规横幅在位（或已列为 R2 前必修项并有排期）；导出/重置可用 |

**任一不满足时的处置**：
- G3 失败 → 修复并复测该缺陷路径（只需复测相关卡，不必全量重跑），通过后重新判定。
- G2/G4 失败 → 卡点记入缺陷清单交 engineering-lead，修复合入后由任一测试者复测对应卡。
- G7 合规项失败 → **无条件阻塞 R2**，不适用"主理人豁免"（合规红线不由单轮测试结果豁免）。

**R1 产出物**：`production/playtests/round-1-report.md`（缺陷分级清单 + 3 张记录表汇总 + G1-G7 判定表 + 结论）。
