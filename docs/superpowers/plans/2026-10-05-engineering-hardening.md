# 工程可靠性与模块边界优化

目标：修复审计中可复现的缺陷，降低 HTTP、异步请求、事件和状态管理的耦合。沿用当前未提交改动，课程与自动化不在修改范围。

基线：应用测试 638/638；关系 runtime 测试 21/21。测试通过不代表不存在未覆盖的错误。

- [x] HTTP：新增 `server/http.js`，将请求解析、CORS 和响应函数从静态资源服务中抽离；旧导出兼容。按 UTF-8 字节限制 2,000,000 字节，拒绝非对象 JSON，超限返回 413 而非直接断开连接；非法路径和目录请求返回受控状态。
- [x] 事件：`core/events.js` 按回调、事件名和订阅实例管理解绑，避免同回调跨事件冲突；脱离 DOM 节点依赖。
- [x] 状态：`core/state.js` 的同步 mutate 使用隔离草稿，异常和保存失败不留下半次变更；保留顶层对象身份以兼容装配层。
- [x] 异步：新增 `core/request-scope.js`，接口 `begin(channel) / cancelAll()`，ticket 提供 `signal / isCurrent() / finish()`；角色、会话和输入变化使旧结果失效。应用生成、优化、计划共享该生命周期，客户端传递取消信号。
- [x] Runtime：退出状态与退出信号优先于冲突、修复和推进，防止工作状态与行动建议矛盾。
- [x] 依赖检查：覆盖 re-export、字面量动态 import；缺失依赖使检查失败，而非静默跳过。
- [x] 启停：统一 Windows 服务身份核验和 PID 归属；失败回滚只操作原始进程对象；后台启动入口拒绝覆盖活 PID 或无法确认的 PID。
- [x] 最终集成：用实际 store 验证回复、训练日志和学习记录一次提交；完成完整回归、语法检查、差异检查和验收文档。

验证：先添加覆盖实际缺陷的回归用例并记录失败，再运行相关测试；最终运行应用完整测试、runtime 测试、依赖图和语法检查。网络测试只访问隔离的本地测试服务器，模型响应使用模拟，不消耗远程模型调用。

交付：实现代码、回归用例、`docs/verification/2026-10-09-engineering-hardening.md`，记录实际完成范围与剩余架构限制；不提交代码。
